# 前提知識：シェルスクリプト

Docker まわりでシェルスクリプトが登場するのは主に2箇所。**コンテナの起動スクリプト（entrypoint.sh）**と、**ビルドやデプロイの自動化**。どちらも「動けばいい」の書き方をすると、コンテナ特有の落とし穴を踏む。

## entrypoint.sh の定番と罠

設定の展開や初期化をしてから本体を起動する、というパターンで entrypoint スクリプトを書くことが多い。

```bash
#!/bin/sh
set -eu

# 環境変数から設定ファイルを生成するなどの前処理
envsubst < /etc/myapp/config.template > /etc/myapp/config.yml

# 最後は exec で本体に置き換わる（これが重要）
exec "$@"
```

最後の `exec` を忘れると、アプリがシェルの子プロセスとして動き、**PID 1 がシェルのままになってコンテナに送られた SIGTERM がアプリに届かない**。結果、`docker stop` のたびに10秒待ってから SIGKILL で殺される（graceful shutdown が効かない）コンテナができあがる。コンテナのシェルスクリプトで最も重要な1行が `exec "$@"`。

また、Alpine ベースだと bash はなく sh（ash）なので、bash 固有の構文（`[[ ]]` や配列）は使えない。`#!/bin/sh` で POSIX 互換に書くか、bash を明示的にインストールする。
