# 前提知識：Web開発

Docker の教材やサンプルは、ほぼ例外なく Web アプリ（API サーバー＋DB）を題材にする。ポート公開、コンテナ間通信、リバースプロキシ——Docker の主要機能は Web 開発の語彙で説明されるので、その語彙を持っているかで学習速度が変わる。

## Docker 学習で前提にされる Web の知識

- **HTTP とポート**: 「コンテナの 8080 をホストの 80 に紐づける」（`-p 80:8080`）が何をしているか。クライアント→サーバーの流れとポート番号の意味
- **API サーバーと DB の分離**: compose のサンプルは大体「web + db」の2コンテナ構成。なぜ分かれているか（[00-07_アプリケーションアーキテクチャ](00-07_アプリケーションアーキテクチャ.md)）
- **リバースプロキシ**: nginx を前段に置く構成が頻出。TLS 終端・ルーティングを前段が担う、という役割分担
- **localhost の罠**: コンテナ内から `localhost:5432` に接続しても**そのコンテナ自身**を指す。隣のコンテナはサービス名（`db:5432`）で呼ぶ——Web 開発の「接続先ホスト」の感覚がないと、この最頻出エラーを自力で解けない

## 最低限のスタートライン

フルスタック開発者である必要はまったくない。「簡単な HTTP API を1本立てて curl で叩ける」程度で十分で、それがあれば Docker 側の学習（[09_コンテナの実行](../09_コンテナの実行/) の compose 実践など）に進める。

```bash
# このレベルの操作が分かればOK
curl -i http://localhost:8080/health
```
