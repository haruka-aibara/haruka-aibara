# 前提知識：シェルコマンド

Docker の学習でシェルコマンドの習熟度がそのまま効いてくるのは、**コンテナの中に入って調査するとき**。`docker exec -it <container> sh` で入った先は素の Linux シェルで、そこで何ができるかは自分のコマンド力次第になる。

## コンテナ内調査でよく使う場面

コンテナ内は最小構成で、使い慣れた道具（ps、curl、vim…）が入っていないことが多い。**基本コマンドの組み合わせで調べ切る力**が問われる。

```bash
docker exec -it api sh

# プロセス確認（ps がない環境では /proc を直接見る）
cat /proc/1/cmdline | tr '\0' ' '

# 設定ファイルの中身と場所を確認
ls -la /etc/myapp/
cat /etc/myapp/config.yml | grep -v '^#'

# 環境変数の確認（設定ミスの定番調査）
env | sort
```

また、Dockerfile の `RUN` に書くのもシェルコマンドそのものだし、ログ調査では `docker logs api 2>&1 | grep ERROR | tail -20` のようにパイプとリダイレクトを日常的に使う。
