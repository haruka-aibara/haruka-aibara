# サードパーティイメージ：コマンドラインユーティリティ

「このツールを使いたいが、ホストに入れたくない／入れられない」。一度しか使わないツール、依存が重いツール、会社PCでインストール権限がないケース——**CLI ツールをインストールせずコンテナとして実行する**パターンで解決できる。

## 基本形：run して即捨てる

```bash
# jq を入れずに JSON を整形
cat data.json | docker run --rm -i ghcr.io/jqlang/jq '.items[].name'

# ImageMagick を入れずに画像変換
docker run --rm -v "$PWD":/work -w /work dpokidov/imagemagick input.png -resize 50% output.png

# Trivy を入れずにイメージの脆弱性スキャン
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy image myapp:latest
```

型は決まっている：

- `--rm`：使い捨て
- `-i`：標準入力をパイプで渡すとき
- `-v "$PWD":/work -w /work`：手元のファイルを処理させるとき（コンテナからはホストのファイルが見えないため）

## alias で「入っているように」使う

毎回長いコマンドを打つのは現実的でないので、常用するものは alias にする：

```bash
alias tf='docker run --rm -it -v "$PWD":/work -w /work hashicorp/terraform:1.9'
tf plan   # ホストに Terraform を入れていないのに使える
```

チーム内のバージョン統一にも効く。「全員 Terraform 1.9 を使う」を「全員この alias（イメージタグ）を使う」に置き換えられ、バージョン管理ツールのインストール案内が不要になる。

## セキュリティの視点：ツールに渡す権限を意識する

便利な反面、`docker run` に付けたマウントがそのままツールの権限になる。

- `-v "$PWD":/work` はカレントディレクトリの読み書きを渡している——信頼できないイメージにやってはいけない
- `-v /var/run/docker.sock:...`（上の Trivy の例）は **Docker デーモンの制御＝実質ホスト root** を渡す。Docker 自体を操作するツールには必要だが、意味を理解して使う
- イメージの出所確認は通常のソフトウェアインストールと同じ重み。Docker Hub の Official Image / Verified Publisher か、ベンダー公式レジストリ（ghcr.io の公式オーガニゼーション等）を選ぶ

「インストールしていないから安全」ではなく、「インストールと同じ信頼判断を、イメージの選択でやっている」という感覚が正しい。
