# サードパーティイメージ：インタラクティブなテスト環境

「Python 3.13 の新機能をちょっと試したい」「この bash スクリプト、Ubuntu 22.04 でも動くか確認したい」——そのためだけに VM を立てたり、ホストに別バージョンを入れたりするのは大げさ。**使い捨ての対話環境を秒で起動する**のは、Docker の日常使いで最も手軽で強力なパターン。

## 基本形：--rm + -it

```bash
docker run --rm -it python:3.13 python    # Python REPL が即起動
docker run --rm -it ubuntu:22.04 bash     # まっさらな Ubuntu シェル
docker run --rm -it node:22 node          # Node.js REPL
```

- `-it`：対話モード（キー入力をコンテナに繋ぐ）
- `--rm`：終了時にコンテナを自動削除。**試し斬り用途では必ず付ける**（付け忘れると停止済みコンテナの死体が溜まっていく）

抜ければ全部消える。ホスト環境は1バイトも汚れない。

## 使いどころのパターン

**言語やライブラリのバージョン差の確認**：

```bash
docker run --rm python:3.11 python -c "import tomllib"   # 3.11 で入ったか確認
docker run --rm python:3.10 python -c "import tomllib"   # → ModuleNotFoundError
```

**「まっさらな環境で再現するか」の切り分け**：手元でだけ起きるバグは、自分の環境の何かが原因か、コードが原因かをまず切り分けたい。素の環境で再現すればコードの問題と確定する。

**手元のファイルを持ち込んで試す**：

```bash
docker run --rm -it -v "$PWD":/work -w /work python:3.13 bash
# /work に現在のディレクトリが見える状態でシェルが起動
```

スクリプトの動作確認・別環境でのビルド確認がホストを汚さずできる。

**壊す実験**：「この rm は何を消すのか」「この設定変更でどうなるか」のような危険な実験も、使い捨てコンテナ内なら安全にできる。セキュリティの学習（攻撃コマンドの挙動確認など）でも、隔離された使い捨て環境として重宝する——ただしカーネル共有である以上、マルウェア検体の実行のような本気の隔離が要る用途には VM を使う（[01-03](../01_Docker_イントロダクション/01-03_ベアメタルvsVMvsコンテナ.md)）。
