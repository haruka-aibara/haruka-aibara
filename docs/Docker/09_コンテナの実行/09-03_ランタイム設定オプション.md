# ランタイム設定オプション

`docker run` の基本（ポート・ボリューム・ネットワーク）は本章の他記事で扱っているので、ここでは**本番運用で効いてくる実行時オプション**——再起動・リソース・ヘルスチェック・権限——をまとめる。「動く」と「運用に耐える」の差はだいたいここに出る。

## 再起動ポリシー：--restart

コンテナが落ちたとき・ホストが再起動したときにどうするか。デフォルトは「何もしない」なので、指定しないと**サーバー再起動でコンテナは全部止まったまま**になる。

```bash
docker run -d --restart unless-stopped nginx
```

- `unless-stopped`：異常終了でもホスト再起動でも復帰。手動 stop したものは復帰しない——常駐サービスの実用解
- `on-failure:5`：異常終了時のみ、5回まで再試行
- クラッシュループ（起動→即死→再起動→…）になっていないかは `docker ps` の STATUS（`Restarting (1) ...`）で分かる

## リソース制限：--memory / --cpus

無制限のコンテナはホストと同居者を巻き込める。本番では必ず付ける（挙動の詳細は [02-02_cgroups](../02_基盤技術/02-02_cgroups.md)）：

```bash
docker run -d --memory=512m --cpus=1.0 --pids-limit=100 myapp
```

## ヘルスチェック：--health-cmd

「プロセスは生きているが応答しない」状態を検知する仕組み。

```bash
docker run -d \
  --health-cmd="curl -fsS http://localhost:8080/health || exit 1" \
  --health-interval=30s --health-retries=3 \
  myapp
```

`docker ps` の STATUS に `(healthy)` / `(unhealthy)` が出るようになり、compose の `depends_on: condition: service_healthy`（「DB が起動しきってからアプリを起動」）にも使える。Dockerfile の `HEALTHCHECK` 命令で焼き込むこともできる。

## 権限を絞る系：本番の既定値にしたいもの

デフォルトのコンテナは意外と多くの権限を持っている。絞る方向のオプション：

```bash
docker run -d \
  --read-only --tmpfs /tmp \        # ルートFSを読み取り専用に（改ざん・永続化を防ぐ）
  --cap-drop=ALL --cap-add=NET_BIND_SERVICE \   # ケーパビリティを必要最小限に
  --security-opt no-new-privileges \            # setuid 等での権限昇格を禁止
  myapp
```

逆方向の `--privileged` は隔離をほぼ全部外すスイッチで、「動かないから privileged を付けたら動いた」は問題を権限で踏み潰しただけ。何のケーパビリティが足りないのかを特定して `--cap-add` で個別に足すのが正しい手順（詳細は [10_コンテナセキュリティ](../10_コンテナセキュリティ/)）。

## 設定の渡し方：-e / --env-file

```bash
docker run -d --env-file ./prod.env myapp
```

環境変数は `docker inspect` で丸見えになる点に注意。DB パスワード等の本物の秘密は、オーケストレータの secret 機構（ECS の Secrets Manager 連携等)で注入する。
