タンパ明示性・タンパ検知性 — 機器が攻撃者の手元にあるとき何ができるか

分解される前提で守る。防げないなら痕跡を残す、検知する、鍵を消す。

何が問題なのか

普段のセキュリティ対策は「攻撃者はネットワークの向こう側にいる」ことを前提にしている。ところが機器そのものが攻撃者の手元にある状況では、その前提が崩れる。IC カード、決済端末、IoT のセンサー、車載機器、鍵を保管する HSM。これらは物理的に持ち出され、分解され、基板にプローブを当てられる。

この状況ではソフトウェアの対策は無力で、筐体と回路の作りで守ることになる。その考え方が耐タンパ性（tamper：いじる、細工する）。

分解しない攻撃もある

物理攻撃は筐体をこじ開けるものだけではない。機器を普通に動作させたまま外から観測する手口があり、これはサイドチャネル攻撃と呼ばれる。

  • 消費電力の解析：暗号処理中の電流の波形から、鍵のビットを推定する
  • 処理時間の測定：計算にかかる時間が鍵の値で変わることを利用する
  • 電磁波の観測：チップから漏れる電磁波を拾う
  • 故障の誘発：電源電圧を一瞬下げる、レーザーを当てるなどして計算を誤らせ、誤った結果から鍵を割り出す

対策はアルゴリズムの実装側で行う。処理時間を入力によらず一定にする、ダミーの演算やノイズを混ぜる、といった作り込みで、暗号ライブラリを自作してはいけない理由の1つでもある。

基準として使えるもの

製品選定や要件定義では、暗号モジュールの評価基準である FIPS 140-3 の認証レベルが共通言語になる。レベルが上がるほど物理的な要求が厳しくなり、上位のレベルでは検知と応答（ゼロ化）まで求められる。「耐タンパの製品を選ぶ」ではなく「求めるレベルの認証を取得している製品を選ぶ」と言えると、調達の要件として書ける。

提案するときの言い方

「鍵をソフトウェアで持つな、HSM を使え」だけでは費用対効果の議論に負ける。「その鍵が漏れたときに何が起きるか」から逆算する——署名鍵が漏れれば自社名義の偽アプリが作られ、回収に数か月かかる。決済端末の鍵が漏れればカード情報が複製される。
逆に、漏れても影響が限定的な鍵に高価な物理対策を要求するのは過剰。鍵ごとに守り方の強さを変える、という設計の話に持ち込む。
