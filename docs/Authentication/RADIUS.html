RADIUS — 認証を機器から引きはがして1か所に集める

アクセスポイントも VPN もスイッチも、自分では判断せず認証サーバに聞きに行く。

何が問題なのか

無線 AP、VPN 装置、ネットワークスイッチ。それぞれの機器がアカウントを持っていると、社員が1人入るたびに全部に登録し、辞めるたびに全部から消すことになる。消し忘れた1台が残り、退職者のアカウントで社内網に入られる——という事故はこの構成から生まれる。

そこで認証を機器から切り離し、専用のサーバに集約する。その通信の取り決めが RADIUS（Remote Authentication Dial-In User Service）。名前のとおりダイヤルアップ時代の生まれだが、いまも無線 LAN と VPN の裏側で動いている。

「オーセンティケータ」が2つの意味で出てくる

ここが混乱しやすい。同じ言葉が、役割の名前とパケットの項目名の両方に使われている。

言葉指しているもの
サプリカント接続しようとする端末。IEEE 802.1X での役割名
オーセンティケータ（役割）AP やスイッチなど、入口となる機器。NAS とも呼ぶ
Authenticator（フィールド）RADIUS パケットの中にある 16 バイトの項目。応答が本物か確かめ、パスワードを隠すのに使う

試験や設計書で「オーセンティケータ」と出てきたら、機器の話なのかパケットの話なのかを文脈で見分ける。

やり取りの流れ

運用で押さえること

  • UDP で動く：認証は 1812 番、アカウンティングは 1813 番。応答がなければ機器側が再送や別サーバへの切り替えを行うので、サーバは冗長化して機器に2台以上登録しておく。
  • 共有シークレットが要：機器とサーバの間に事前に設定する固定文字列。これで応答の真正性を検証し、パスワード属性を隠している。機器ごとに別の値にする、十分長くする、設定手順書に平文で残さない。
  • プロトコル自体の保護は弱い：隠蔽の仕組みが MD5 ベースで古い。経路が信用できない区間（拠点間・クラウド接続）では、IPsec で包むか TLS 版（RADIUS over TLS、RadSec）を使う。
