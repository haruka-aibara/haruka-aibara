# インストール済みパッケージの一覧

「このサーバーに何が入っているか」を答えられないと困る場面は多い。脆弱性が公表されて影響範囲を調べるとき（「うちの openssl はどのバージョン？」）、古いサーバーを新環境に移設するとき、構成管理コードに落とすとき。全部この一覧が出発点になる。

## 一覧を出す

```bash
# Debian/Ubuntu
apt list --installed

# RHEL/Fedora
dnf list --installed
```

数千行出てくるので、実際には grep と組み合わせて使うことがほとんど。

```bash
apt list --installed 2>/dev/null | grep openssl
dnf list --installed | grep openssl
```

## 特定パッケージの詳細を掘る

脆弱性対応では「入っているか」だけでなく「どのバージョンか」「どのファイルを撒いたか」まで見る。

```bash
# バージョン確認
dpkg -l openssl          # Debian/Ubuntu
rpm -q openssl           # RHEL/Fedora

# そのパッケージが配置したファイル一覧
dpkg -L openssl
rpm -ql openssl

# 逆引き：このファイルはどのパッケージのものか
dpkg -S /usr/bin/openssl
rpm -qf /usr/bin/openssl
```

逆引きは「見覚えのないバイナリが置かれている」ことに気づいたときの調査にも使える。どのパッケージにも属さないバイナリが `/usr/bin` にある、というのは手動配置か侵害の痕跡かのどちらかで、いずれにせよ確認対象になる。

## 「手動で入れたもの」だけを見る

移設や構成管理コード化のときに欲しいのは、依存で自動的に入ったものを除いた「人が意図して入れたパッケージ」のリスト。

```bash
apt-mark showmanual      # Debian/Ubuntu
dnf repoquery --userinstalled   # RHEL/Fedora
```

これをそのまま Ansible や Dockerfile のパッケージリストの叩き台にできる。
