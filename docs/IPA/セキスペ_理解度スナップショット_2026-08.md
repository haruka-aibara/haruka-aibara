## 第1章 脅威とサイバー攻撃の手法

| 用語 | Lv | 言えたこと | 抜け・誤解 |
|---|---|---|---|
| WEP / WPA / WPA2 / ESSID | 1 | ESSID はアクセスポイントに付く識別子（最大32文字）。ステルスモードで隠せる | WEP が破られる理由、WPA→WPA2 の変化が出てこない。ステルスモードを対策として評価していたが、ESSID は接続時に平文で流れるので防御にはならない |
| Pass the Hash | 2 | パスワードそのものを知らなくても、ハッシュを入手すればサーバ側の認証を通せる | 入手経路を盗聴と捉えていた（実際は侵入後のメモリ/SAM ダンプが主）。チャレンジレスポンスなのでリプレイとは別物 |
| TCP SYN Flood | 2 | SYN を送るとサーバは SYN/ACK を返して応答を待つ。この待ちが大量に積み上がる | 埋まるのがバックログキューという固定長の枠であること、SYN Cookie による回避 |
| DNS 水責め攻撃 | 1 | 存在しないサブドメインへの問い合わせを、送信元を偽って送る | 何が起きるのか（キャッシュに載らないためキャッシュサーバと権威サーバが枯渇する）が出てこない |
| マルチベクトル型 DDoS | 2 | 単一の手法ではなく、別プロトコル・別送信元など複数を組み合わせて防御側の対処を困難にする | — |
| XSS の手順（セッションハイジャック） | 2 | スクリプトを踏ませて Cookie 内のセッション ID を攻撃者に送らせ、そのIDでサーバと通信する | 「使い回されたセッション ID はサーバ側が破棄する」と考えていたが、実際は攻撃者と正規ユーザが同じセッションを同時に使える |

名前だけ（Lv1）：IP スプーフィング / Smurf 攻撃 / DRDoS / EDoS・DeOS・NTP リフレクション / XSS の3分類（Reflected・Stored・DOM based） / BadNets

## 第3章 セキュリティ技術（暗号と認証）

| 用語 | Lv | 言えたこと | 抜け・誤解 |
|---|---|---|---|

| ブロック暗号（ECB / CBC / OFB / 3DES） | 1 | 決まった長さのブロックごとに暗号化する。同じ内容が同じ暗号文として現れる問題がある | 対策をパディングや並べ替えと捉えていた（実際は前のブロックとの連鎖と IV）。「今のデファクトは CBC」と認識していたが、現在は GCM |

| CRL | 2 | 有効期限前に証明書を失効させるためのリスト。失効の申請を出せる | — |
| Kerberos | 2 | Active Directory で使われている認証方式。チケットを受け取り、それを持って複数のサーバに SSO できる | realm / KDC / AS / TGS といった構成要素と認証の流れ |
| TLS ダウングレード / ロールバック / POODLE | 2 | サーバが複数バージョンを受け付けていると、クライアントが「古いものしか使えない」と主張して古い方に合わせさせられる。その結果、古いバージョン固有の脆弱性を突かれる。対策は古いバージョンを受け付けないこと | — |
| MIME | 2 | メールにバイナリを載せられるようにした仕組み。Base64 でバイナリを64種類の文字に変換して埋め込む | — |

| UEFI | 3 | BIOS を置き換えるもので、署名された OS だけを起動する。OS 起動前に入り込むタイプのマルウェアを、署名がないことを理由にブートさせない。失効リストの仕組みがあり、更新が配信されることがある | — |
| 時刻同期方式 | 1 | NTP の話かと思ったが、暗号・認証の文脈では別のものらしい、というところまで | 実体はワンタイムパスワードの生成方式（トークンとサーバで時刻を共有する） |
| RADIUS のオーセンティケータ / サプリカント | 1 | サプリカント＝認証されたい側 | オーセンティケータを RADIUS 認証サーバと捉えていたが、実際は認証を仲介する装置（スイッチや AP）。RADIUS サーバは認証サーバ |

| S/MIME | 1 | MIME のセキュア版 | 何をどう守るのか |
| タンパ明示性 / タンパ検知性 | 1 | タンパ＝いじる、という語感。VOID の文字が浮かぶシールのような例を挙げられた | その例は「明示性」の側。検知性は機器が改ざんを検出して鍵を消去するなどの反応をする性質 |
| IC カードと磁気カード | 1 | 磁気カードは読み取られたら終わり。IC カードはそうではない | IC カードがなぜ安全なのかを説明できない |

## この時点での傾向

- **概念や運用の話は 2 前後で答えられるが、プロトコルの中身（ヘッダの構成、鍵交換の手順、暗号アルゴリズム）はほぼ 1**
- 実務で触っている領域（サブネット設計、証明書の種類、セキュアブート）だけレベルが上がっている
- 混同が起きやすいのは、**似た名前で別物のペア**（コリジョンドメイン↔ブロードキャストドメイン、タンパ明示性↔検知性、オーセンティケータ↔認証サーバ、時刻同期方式↔NTP）
