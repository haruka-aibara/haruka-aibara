# いらないページを消せる状態を作る

「このページ、もう要らないよな」と思うことはある。問題はその次で、**自分の判断で消していいのか分からない**。誰かが今も使っているかもしれないし、消した後で困る人が出たら自分の責任になる。だから「まあ置いとこ」になる。

全員が同じことを考えるので、誰も消さない。ドキュメントが増える一方なのは、いらないページが見つからないからではなく、**見つけた人が消す判断を背負えないから**だ。

## 詰まっているのは判断材料ではなく権限

放置が合理的な選択になる構造がある。

- 消して困る人が出たら、消した個人の責任になる
- 残しても、短期的には誰も文句を言わない

損得が非対称なので、**個人に判断を委ねている限り、答えは常に「置いとく」になる**。判断材料を増やしても、この非対称は解けない。

一方で残すコストは実在する。検索結果が古い情報で埋まる。新しく入った人が更新されていない手順を踏んでしまう。**更新されていないドキュメントは、無いより悪い。**

## 「消してよいか」を気軽に立てられる場を作る

解き方は、個人の決断を**定例の議題**に変えること。言い出しっぺが個人にならない形にすれば、非対称が消える。

- **決まったタイミングで、消す話だけをする短い枠を作る**（月1で15分程度）
- 立てるのは「消す提案」ではなく **「消してよいか、という質問」**。提案だと通す責任が発生するが、質問なら気軽に出せる
- **候補に挙げるのはラベルを付けるだけ**にする。理由を書かせると誰も挙げなくなる
- 反対する側が「誰が・何のために使っているか」を1行で言う。言えなければ消す側に倒す
- **既定を決めておく**：誰も反対しなければ2週間後に消える、など。この既定があるから、個人が背負わずに済む

扱う対象は毎回5〜10ページに絞る。多いと決まらないし、決まらない会が続くと枠自体が消える。

## 戻せる形で消す

心理的なハードルを下げるいちばん確実な方法は、**戻せるようにしておくこと**。

1. アクセス状況を見る（直近1年で開かれているか）
2. 期限を切って予告する（「◯日に削除します。必要なら声をかけてください」）
3. 削除ではなく**アーカイブに退避**する
4. 一定期間（3か月程度）誰も困らなければ本削除
5. 被リンクを確認し、参照元があれば張り替える

「アーカイブ」という中間状態があるだけで、議論はかなり通りやすくなる。

## 迷ったときの問い

- 直近1年、開かれているか
- 最後に更新されたのはいつか。いまの構成と合っているか
- 同じことが他のページに書かれていないか
- **消して困る人を名指しできるか。** できないなら消す側に倒す
- 「いつか使うかも」は残す理由にならない

例外は、**判断の記録と証跡**。設計判断の記録（ADR）、インシデントの記録、契約や監査で必要になるものは、アクセスがなくても消さない。これらは「読まれる」ためではなく「後から参照できる」ために存在するので、アクセス数で判断すると間違える。

## 整理は「減らしてから」やると早い

もう一つ詰まりやすいのが、階層やラベルの作り直し——いわゆる「ドキュメント整理」のほうだ。ページ数が多いほど設計が難しく、着手コストが跳ね上がるので、いつまでも始まらない。

順番を逆にすると進む。

> **①消して減らす → ②残ったものを整理する**

減った状態なら整理そのものが短時間で終わるので、着手しやすい。逆順にすると、**消える予定のページのために構造を設計する**ことになり、その手間はまるごと無駄になる。

そして「ドキュメント整理プロジェクト」を立てないこと。大きく構えるほど、承認と期間と担当者が必要になって始まらなくなる。月1の15分を続けるほうが、結果的に早く終わる。
