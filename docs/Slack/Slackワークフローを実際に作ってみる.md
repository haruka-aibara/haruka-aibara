# Slack ワークフローを実際に作ってみる

[Slack ワークフローの作り方](./Slackワークフローの作り方.md) の「実際の作成手順」を、キャプチャを取りながらそのまま実行した記録。今回は「絵文字リアクションが使用された時」をトリガーにするワークフローを作る。

## 1. ワークフロー作成画面を開く

サイドバーの `ツール` → `ワークフロー` から、`＋新規` でワークフロー作成画面を開く。

![ワークフロー作成画面](<assets/Slackワークフローを実際に作ってみる/image-1.png>)

## 2. 新規ワークフローの編集画面が開く

「イベントを選択する」からトリガーを設定していく。

![イベント選択画面](<assets/Slackワークフローを実際に作ってみる/image-2.png>)

## 3. トリガーを選ぶ

トリガー候補の中から「絵文字リアクションが使用された時」を選択する。

![トリガー選択画面（絵文字リアクションが使用された時）](<assets/Slackワークフローを実際に作ってみる/image-3.png>)

## 4. 対象の絵文字とチャンネルを設定する

反応する絵文字と、対象チャンネル（`slack-workflow-test`）を指定する。

![絵文字・チャンネル設定画面](<assets/Slackワークフローを実際に作ってみる/image-4.png>)

`:muscle:`（すべての肌色）を選択し、`続行する` を押せる状態になった。

![絵文字選択後の設定画面](<assets/Slackワークフローを実際に作ってみる/image-5.png>)

## 5. トリガー設定完了、ステップ追加へ

トリガーが「`slack-workflow-test` で `muscle::skin-tone` を使ってほかのメンバーがリアクションしたら開始する」に確定した。次は「ステップを追加する」でワークフローの中身を作っていく。

![トリガー設定完了画面](<assets/Slackワークフローを実際に作ってみる/image-6.png>)

## 6. ステップを選ぶ

「メッセージ」カテゴリの中から「スレッドでメッセージに返信する」を選択する。

![ステップ選択画面（スレッドでメッセージに返信する）](<assets/Slackワークフローを実際に作ってみる/image-7.png>)

## 7. 返信内容を設定する

返信先は「リアクションされたメッセージへの参照」（トリガーの変数）を選び、本文に `💪 スタンプが押されました！` を入力する。

![返信内容設定画面](<assets/Slackワークフローを実際に作ってみる/image-8.png>)

## 8. ステップ追加完了

「1. スレッドでメッセージに返信する」がステップとして追加され、返信プレビューも確認できる状態になった。

![ステップ追加完了画面](<assets/Slackワークフローを実際に作ってみる/image-9.png>)

## 9. さらに別チャンネルへメッセージ送信するステップを追加

続けて、別チャンネルにも通知したいので「メッセージ」カテゴリから今度は「チャンネルへメッセージを送信する」を選択する。

![ステップ選択画面（チャンネルへメッセージを送信する）](<assets/Slackワークフローを実際に作ってみる/image-10.png>)

## 10. 送信先チャンネルとメッセージ内容を設定する

送信先チャンネルに `slack-workflow-test-2` を選び、本文に「どこかのチャンネルで 💪 スタンプが押されました！ご確認ください。」を入力する。

![送信先・メッセージ内容設定画面](<assets/Slackワークフローを実際に作ってみる/image-11.png>)

## 11. 2つ目のステップも追加完了

「2. `slack-workflow-test-2` にメッセージを送信する」がステップとして追加された。これでトリガー1つ・ステップ2つの構成になった。

![2ステップ目追加完了画面](<assets/Slackワークフローを実際に作ってみる/image-12.png>)

## 12. 権限設定をする

右上の `...` メニューから「権限」を開き、このワークフローを実行できる人を設定する。

![`...` メニュー（権限）](<assets/Slackワークフローを実際に作ってみる/image-13.png>)

「権限」ダイアログには、ワークフローマネージャー（編集・公開・削除ができる人）、このワークフローを誰が検索できるか、誰がコピーできるか、をそれぞれ設定する項目がある。個人検証では初期値のままでもいいが、企業利用では検索範囲・コピー範囲まできちんと絞ったほうがよさそう。

![権限ダイアログ](<assets/Slackワークフローを実際に作ってみる/image-14.png>)

## 13. ワークフロー名と説明を入れる

タイトル横の「詳細を編集する」から、ワークフロー名と説明を設定できる。今回は `マッスル速報` という名前にする（💪 スタンプの反応を検知して知らせるワークフローなので）。説明文は「`slack-workflow-test` で誰かが 💪 リアクションを押したら、スレッド返信と別チャンネルへの通知で即座に知らせる速報ワークフローです」とした。

![「詳細を編集する」ボタン](<assets/Slackワークフローを実際に作ってみる/image-15.png>)

「ワークフローの詳細」ダイアログで名前と説明を入力し、アイコンもアップロードできる。保存するとタイトル部分に反映される。

![ワークフローの詳細ダイアログ（名前・説明を入力）](<assets/Slackワークフローを実際に作ってみる/image-16.png>)

## 14. 公開前の最終確認

タイトルが「マッスル速報」、説明文も反映された状態。トリガー1つ・ステップ2つの構成が最終形。まだ右上のステータスは「未公開」なので、この後「公開する」を押して実際に 💪 リアクションで動作確認する。

![公開前の最終画面](<assets/Slackワークフローを実際に作ってみる/image-17.png>)

## 15. 「完了」を押すと公開前の確認ダイアログが出る

右上の `完了` を押すと、そのまま公開されるわけではなく「公開前にワークフローの詳細と権限が正しいことを確認してください」という確認ダイアログが開く。名前・説明・権限をここで最終チェックし、問題なければ `公開する` を押す。

![公開前確認ダイアログ](<assets/Slackワークフローを実際に作ってみる/image-18.png>)

## 16. 公開完了

「マッスル速報 が公開されました！」の画面が表示され、右上のステータスも「未公開」から「公開する」（公開済み表示）に変わった。ここでは「チャンネルを選択する」から、任意のチャンネルの「ワークフロー」タブにこのワークフローを追加することもできる（必須ではない）。

![公開完了画面](<assets/Slackワークフローを実際に作ってみる/image-19.png>)

なお「チャンネルに追加する」は必須ではない。今回のような絵文字リアクションなどのイベント駆動型トリガーは、トリガー設定の時点でチャンネルと紐づいているのでこのまま動く。「チャンネルに追加する」が意味を持つのは、リンク・ボタンから起動する手動トリガー型のワークフローで、チャンネルの `Workflows` タブに起動導線を置きたい場合。

## 17. 実際に動作確認

`slack-workflow-test` の適当なメッセージに 💪 リアクションをつけたところ、スレッドに「マッスル速報」から「💪 スタンプが押されました！」と返信が届いた。狙いどおり動作した。

![動作確認：スレッド返信が届いた画面](<assets/Slackワークフローを実際に作ってみる/image-20.png>)

もう1つのステップ（別チャンネルへの通知）も確認。`slack-workflow-test-2` に「マッスル速報」から「どこかのチャンネルで 💪 スタンプが押されました！ご確認ください。」が届いており、トリガー1つ・ステップ2つとも狙いどおり動作した。

![動作確認：別チャンネルへの通知が届いた画面](<assets/Slackワークフローを実際に作ってみる/image-21.png>)

## まとめ：Terraform 化は必要か

このクラシック Workflow Builder（トリガー＋ステップの GUI）には、作成・更新用の公開 API が存在しない。Terraform の Slack provider（community 製）もチャンネルやユーザーグループは管理できるが、ワークフロー定義はカバー対象外。コードで管理したいなら Deno Slack SDK / Bolt を使った別の（コードベースの）ワークフロー基盤に乗り換える必要があり、今回作った程度の規模・変更頻度ではその移行コストは見合わない。UI での手動管理で十分。
