楕円曲線暗号 — なぜ 256 ビットで RSA 3072 ビットと同じ強さなのか

鍵が10分の1の長さなのに安全と言われる理由と、選ぶときに見る点。

何が問題なのか

証明書を発行するとき、SSH 鍵を作るとき、KMS でキーを作るときに「RSA 2048 か、ECDSA P-256 か」を選ばされる。片方は 2048 ビット、もう片方は 256 ビット。短いほうが安全なわけがないという直感が邪魔をして、なんとなく RSA を選び続けることになる。ここは理屈を1つ知っておくと迷わなくなる。

強度の源が違う

RSA の安全性は「大きな数の素因数分解が難しい」ことに依存する。ところが素因数分解には数体ふるい法という、総当たりよりずっと速い解法が知られている。だから安全性を保つには鍵をどんどん長くするしかない。

楕円曲線暗号（ECC）が依存するのは「楕円曲線上の離散対数問題」で、こちらには同種の高速な解法が見つかっていない。総当たりに近いコストがかかるので、短い鍵で同じ強度が出せる。

何をしているのか

楕円曲線上には「2点から3点目を決める」加算のルールが定義されている。ある点 P を k 回足した点 Q（= kP）を求めるのは速いが、P と Q から k を逆算する方法が知られていない。この k が秘密鍵、Q が公開鍵にあたる。

実務で選ぶとき

  • 用途は2つ：鍵交換なら ECDH / ECDHE、署名なら ECDSA または EdDSA（Ed25519）。データそのものの暗号化には使わない。
  • 曲線は決め打ちでよい：TLS 証明書やクラウドの鍵管理では P-256（secp256r1）、SSH 鍵なら Ed25519。迷ったらこれで足りる。
  • 互換性だけが RSA の残る理由：古い機器や決済端末が ECDSA を解さないことがある。相手を選べない公開サービスでは RSA と ECDSA の証明書を両方置く構成も取られる。

ECDSA は署名のたびに乱数が要る

この乱数を使い回すと、2つの署名から秘密鍵が計算で復元できる。PlayStation 3 の署名鍵が漏れた事件も、Bitcoin ウォレットからの鍵漏洩も原因はこれ。自前で署名を実装するのでなければ気にしなくてよいが、乱数生成器が貧弱な組込み環境では現実に起きる。乱数を使わない決定論的な方式（Ed25519、RFC 6979 の ECDSA）を選べばこの危険は消える。
