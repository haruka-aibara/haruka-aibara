# AESとブロック暗号モード — 試験で要るのはどこまでか

「AES-CBC」「AES-GCM」という文字列は TLS の設定ファイルにも試験問題にも出てくる。でも中身を調べにいくと S-box だのラウンド関数だのが出てきて、どこまで理解すればいいのか分からなくなる。

先に結論を言うと、**AES 本体の中身は理解しなくていい。理解が要るのは「モード」のほう**。そしてモードは配線図1個で説明がつく。

## そもそもなぜ「モード」なんてものがあるのか

AES には制約がある。**一度に 16 バイトしか暗号化できない**。

16 バイトしか入らない小さい金庫だと思えばいい。それが AES の正体で、鍵長が 128/192/256 bit と選べるのは金庫の鍵の複雑さの話にすぎない。ブロック長は 128 bit（16 バイト）固定。

しかし現実に暗号化したいのは、もっと長い文章やファイルである。だから **16 バイトずつブツ切りにして、金庫をいくつも並べる**しかない。

この「並べ方のルール」が**モード**。ECB・CBC・CTR・GCM はすべて並べ方の流派の名前であって、暗号アルゴリズムそのものではない。

## 並べ方の流派

### ECB — 素直に並べるだけ（使ってはいけない）

```
平文1 → [AES] → 暗号文1
平文2 → [AES] → 暗号文2
平文3 → [AES] → 暗号文3
```

ブツ切りにして、それぞれ独立に金庫へ入れる。

問題は、**同じ平文ブロックからは必ず同じ暗号文ブロックが出てくる**こと。暗号文を眺めた攻撃者に「この2箇所は元が同じ文字列だな」と分かってしまう。画像を ECB で暗号化すると元絵の輪郭が透けて見える例（通称ペンギン画像）が有名。

### CBC — 前のブロックと混ぜてから入れる

```
        IV ──┐
平文1 ──XOR──┴→ [AES] → 暗号文1 ──┐
平文2 ──XOR───────────────────────┴→ [AES] → 暗号文2 ──┐
平文3 ──XOR───────────────────────────────────────────┴→ [AES] → 暗号文3
```

式にすると一行で終わる。

```
暗号文_n = AES暗号化( 平文_n XOR 暗号文_(n-1) )
※ 最初のブロックだけ、暗号文_0 の代わりに IV を使う
```

前のブロックの暗号文を混ぜてから金庫に入れるので、同じ平文でも毎回違う暗号文になる。ECB の問題はこれで消える。

1個目には「前のブロック」が存在しないので、代わりのダミーを用意する。それが **IV（初期化ベクタ）**。IV は秘密にする必要はない（暗号文と一緒に送ってよい）が、**予測可能だとアウト**。毎回ランダムに変える。

この配線図1個から、試験で問われることが全部導出できる：

| 配線から導かれる性質 | 帰結 |
|---|---|
| 前のブロックと XOR する | 同じ平文でも暗号文が変わる（ECB の弱点が消える） |
| IV が先頭ブロックに直結している | IV が予測可能だと先頭を推測できる → **BEAST 攻撃** |
| 暗号化に「前の暗号文」が要る | 暗号化は並列化できない（復号は可能） |
| ブロック長にそろえる必要がある | パディングが要る → **パディングオラクル攻撃** |

暗記項目が4つバラバラにあるのではなく、配線図から生えている。

### CTR — カウンタを暗号化して XOR する

平文そのものは金庫に入れない。カウンタ値を暗号化して鍵ストリームを作り、平文と XOR する。ブロックが互いに独立するので**並列化できる**し、パディングも不要。GCM のベースになっている。

### GCM — CBC の弱点を埋めた現在の標準

CBC には決定的な穴がある。**中身を隠せるだけで、途中で書き換えられたかどうかが分からない**（機密性はあるが完全性がない）。だから CBC 単体では不十分で、MAC と併用する必要がある（Encrypt-then-MAC）。

GCM は CTR モードに認証タグを組み合わせたもので、**暗号化と改ざん検知を同時に行う**。こういう方式を **AEAD**（認証付き暗号）と呼び、GCM・CCM・ChaCha20-Poly1305 がその仲間。

TLS 1.3 では CBC 系の暗号スイートは全廃され、AEAD のみになった。「今どき CBC が有効になっている＝設定として古い」と読める。

## 攻撃名の位置づけ

出てくる攻撃名は、どれも「CBC の配線の粗を突いたもの」として整理できる。個別に覚えるより、どの配線が原因かで紐づけたほうが早い。

| 攻撃 | 突かれている配線 |
|---|---|
| BEAST | IV が予測可能（TLS 1.0 の CBC で IV を前レコードから流用していた） |
| パディングオラクル / POODLE | パディングが必要という CBC の宿命 |
| ECB のパターン露出 | 同じ平文→同じ暗号文 |

## 結局どこまで覚えるか

**要らない**：S-box の中身、SubBytes / MixColumns などのラウンド関数、鍵スケジュール。試験で問われることはまずない。数学も出てこない。

**要る**：

- AES は共通鍵（対称）暗号。ブロック長 128 bit 固定、鍵長 128/192/256 bit。CRYPTREC 電子政府推奨暗号リストに掲載
- モードとは「16 バイトずつブツ切りにしたブロックの繋ぎ方」
- ECB は同じ平文が同じ暗号文になるので使わない
- CBC は前の暗号文と XOR して連鎖。IV は毎回ランダム、秘密不要
- CBC は機密性のみ。完全性は別途 MAC が必要
- GCM は暗号化＋改ざん検知（AEAD）。TLS 1.3 は AEAD のみ

午前で問われるとしても「CBC モードの説明として正しいものはどれか」程度の粒度。午後では「この暗号スイート設定の問題点を指摘せよ」という形で出る。上の配線図が描ければ足りる。

なお、時間の配分としては AES の中身より **TLS のハンドシェイク・証明書検証・鍵交換（DH / ECDHE、PFS）** のほうが優先度が高い。午後で手を動かさされるのはそちら。
