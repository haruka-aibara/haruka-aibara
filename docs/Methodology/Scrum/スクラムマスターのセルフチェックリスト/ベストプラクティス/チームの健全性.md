# チームの健全性のチェックリスト

自己管理と心理的安全性。イベントが完璧でも、ここが崩れていると長続きしない。

- [ ] 悪いニュース（遅延・障害・ミス）が早い段階で共有される
- [ ] 意見の対立が表面化し、建設的に処理されている（対立ゼロは「議論していない」兆候として扱う）
- [ ] 特定の人にしかできない作業が特定され、減らす取り組み（ペア作業・ドキュメント化）が動いている
- [ ] 改善の提案がスクラムマスター以外のメンバーからも出てくる
- [ ] チームが自分たちで作業の割り当てを決めている（誰かがアサインしていない）

## なぜ属人化は「握りしめ」られるのか

属人化を解消しようとするとき、知識を握っている本人の抵抗に遭うことがある。これを性格やモラルの問題として扱うと解けない。握りしめは本人の視点では**合理的な戦略**だからだ。雇用や評価がゼロサムに見える組織では、「自分にしかできない作業」は交渉力になる。だから「チームのために共有しよう」という道徳的な説得は、本人には一方的な武装解除の要求に聞こえて、握りは固くなるだけ。

ただし、その安心感には構造的な欠陥がある。

1. **代替不可能＝昇進不可能**：「あの人を外すと回らない」は、クビにできない理由であると同時に、異動も昇進もさせられない理由。握りしめた本人が握りしめたものに繋がれる金の檻で、休暇中も呼ばれる永久オンコール付き
2. **資産の一極集中**：その安全は「この会社の、このシステムが存続する限り」しか成立しない。社内特定システムの知識は転職市場でほぼ換金できず、握っている間に老化していく。全財産を1銘柄に突っ込んだポートフォリオと同じ
3. **組織はいずれ迂回する**：バス係数1のリスクを組織が永遠に許容することはない。穏当にはペア作業で引き剥がされ、非常時にはシステムごと作り直されて知識ごと無価値化される。握りが強いほど「本人ごと迂回する」計画の起案理由になる
4. **囚人のジレンマ**：全員が個別に合理的に握りしめると、チーム全体が脆くなり、プロジェクトの失敗確率が上がり、結果として全員の雇用リスクが上がる

本人に伝えるべき本質はこれ：**ジュニアの価値は「自分ができること」で測られ、シニアの価値は「他人をできるようにさせたこと」で測られる**。前者（握った知識）は場所に縛られた資産、後者（人を立ち上げた実績）はレジュメに書けて転職先に持っていける資産。引き継ぎは「安全を手放す」ことではなく、縛られた資産から持ち運べる資産への乗り換え。

スクラムマスターとしての処方：

- **正面から引き剥がさない**。「共有しろ」「ドキュメント書け」の圧は握りを固くするだけ
- **次の行き先とセットで引き継がせる**。「これを手放せる。君には次に X をやってほしいから」。行き先のない引き継ぎ要求は、本人にとって単なる資産没収
- **評価が報いる先を変える**。「自分を代替可能にした人」が昇進する前例が一つあると、握りしめの損得勘定そのものが変わる。逆に握っている人が評価され続ける組織では何を言っても無駄
- **検知は責めずにやる**。「この作業、○○さんが休んだら止まるよね」をレトロで淡々と可視化し、ペア・モブ作業を監査ではなく通常の働き方として入れる

なお、短期的には握りしめが本当に本人を守るケースはある（リストラが進行中なら来月の生存には効くかもしれない）。だからこれは「握りしめは無意味」という話ではなく、**短期の安心を長期の選択肢（昇進・異動・市場価値・休暇）で買っている高利の借金**である、という話。
