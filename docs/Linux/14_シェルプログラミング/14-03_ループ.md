# ループ

「この処理を全サーバーに」「ログファイル全部に同じ変換を」「サービスが上がるまで待つ」——同じことの繰り返しはループに任せる。シェルには for / while / until の3種があるが、実務での使い分けはパターンがはっきりしている。

## for：リストの各要素に対して

```bash
for env in dev staging prod; do
  echo "deploying to $env"
done

for f in /var/log/myapp/*.log; do
  gzip "$f"
done

for i in {1..5}; do
  curl -s "https://api.example.com/health" && break
  sleep 2
done
```

ファイル群への一括処理は glob（`*.log`）をそのまま回すのが正しい形。**`for f in $(ls *.log)` と書いてはいけない**——ファイル名に空白があると壊れる、シェル初心者記事に最も蔓延しているアンチパターン。glob なら空白入りファイル名でも安全。

## while：条件が満たされている間

実務で while が登場する場面は実質2つ。

**1. 「〜になるまで待つ」ポーリング**：

```bash
while ! systemctl is-active --quiet myapp; do
  echo "waiting for myapp..."
  sleep 3
done
```

**2. ファイルを1行ずつ処理する**：

```bash
while IFS= read -r host; do
  ssh "$host" 'uptime'
done < hosts.txt
```

この `while IFS= read -r` は行単位処理の定型句としてこのまま暗記してよい（`IFS=` が前後の空白の消失を、`-r` がバックスラッシュの解釈を防ぐ）。`for line in $(cat file)` は行ではなく単語で分割されるので、行処理には使えない。

until は「条件が真になるまで」で、`while !` と等価。どちらか読みやすいほうでよい（while だけ覚えれば足りる)。

## break / continue

```bash
for f in *.csv; do
  [[ "$f" == "header.csv" ]] && continue   # スキップして次へ
  process "$f" || break                     # 失敗したら打ち切り
done
```

## ループの中で失敗をどう扱うか決めておく

100台に配るループの3台目で失敗したとき、止まるのか・続けるのか・最後にまとめて報告するのか。書く前に決めておかないと、`set -e` 環境では即死し、なければ黙って全部「成功」に見える。まとめて報告する形はこう：

```bash
failed=()
for host in $(< hosts.txt); do
  ssh "$host" 'sudo systemctl restart myapp' || failed+=("$host")
done
(( ${#failed[@]} == 0 )) || { echo "failed: ${failed[*]}" >&2; exit 1; }
```
