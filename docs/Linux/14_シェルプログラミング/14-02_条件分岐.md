# 条件分岐

「ファイルがあったら読む」「引数がなければ usage を出して終わる」「本番環境のときだけ確認を挟む」——スクリプトを書けば必ず分岐が要る。シェルの if は他言語と見た目が似ているせいで、シェル特有のルールを知らずに書いて踏み抜きやすい。

## 基本形と、シェル特有の本質

```bash
if [[ -f /etc/myapp/config.yml ]]; then
  echo "config found"
elif [[ -f ./config.yml ]]; then
  echo "using local config"
else
  echo "no config" >&2
  exit 1
fi
```

押さえるべき本質はひとつ：**シェルの if が見ているのは「コマンドの終了コード」**（0 = 真）。`[[ ... ]]` は条件を評価して終了コードを返す仕組みに過ぎない。だからコマンドを直接条件にできる：

```bash
if systemctl is-active --quiet nginx; then
  echo "running"
fi

if ! grep -q "ERROR" app.log; then
  echo "clean"
fi
```

「コマンドの成否で分岐」がシェルの得意分野で、むしろこちらが本来の姿。

## よく使う判定

```bash
[[ -f path ]]     # ファイルが存在する
[[ -d path ]]     # ディレクトリが存在する
[[ -z "$var" ]]   # 文字列が空
[[ -n "$var" ]]   # 文字列が空でない
[[ "$a" == "$b" ]]   # 文字列比較
(( count > 10 ))     # 数値比較は (( )) が読みやすい
```

数値比較を `[[ $a > $b ]]` と書くと**文字列として**比較される（`10 > 9` が偽になる）罠があるので、数値は `(( ))` か `-gt` を使う。

## [ と [[ の違い：新規に書くなら [[

歴史的な `[`（test コマンド）と bash 拡張の `[[` があり、既存コードでは混在している。`[[` は変数のクォート忘れに寛容で、`&&` や パターンマッチ（`[[ $host == web-* ]]`）も使える。POSIX sh 互換が必要（`#!/bin/sh` で書く）場合以外は `[[` に統一してよい。ただし `[` を使う場面では変数のクォートが必須（`[ -n "$var" ]`）。

## 短絡評価：1行で済む分岐

ログ1行・ガード節程度なら `&&` / `||` が簡潔：

```bash
[[ -d "$BACKUP_DIR" ]] || mkdir -p "$BACKUP_DIR"
[[ $# -ge 1 ]] || { echo "usage: $0 <env>" >&2; exit 1; }
```

ただし `A && B || C` を if-else の代わりに使うのは、B が失敗したときも C が走るという罠があるので避ける。分岐が2方向あるなら素直に if を書く。
