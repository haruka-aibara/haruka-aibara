# IPルーティング

「このホストからあの宛先に、なぜ届かないのか／どの NIC から出ていくのか」。NIC が複数あるサーバー、VPN を張った端末、VPC ピアリングした環境——経路が絡む問題は、ルーティングテーブルを読めれば大半が説明できる。

## パケットの行き先はルーティングテーブルが決める

カーネルは送信のたびにルーティングテーブルを引き、**宛先に最も具体的にマッチする経路**（ロンゲストマッチ）を選ぶ。

```bash
ip route show
```

```
default via 10.0.1.1 dev eth0 proto dhcp
10.0.1.0/24 dev eth0 proto kernel scope link src 10.0.1.15
10.8.0.0/16 via 10.8.0.1 dev tun0
```

読み方：

- `10.0.1.0/24 dev eth0 ... scope link` — このサブネット宛は eth0 から直接届く（ゲートウェイ不要）
- `10.8.0.0/16 via 10.8.0.1 dev tun0` — この範囲は VPN トンネル経由
- `default via 10.0.1.1` — どれにもマッチしなければ 10.0.1.1（デフォルトゲートウェイ）へ

`/24` は `/16` より具体的なので優先される。「VPN につないだら社内には届くが外に出られなくなった」類の問題は、この優先順位とデフォルト経路の奪い合いで説明がつく。

## 一番使う調査コマンド

テーブル全体を眺めるより、「この宛先はどう出ていくのか」をピンポイントで聞くほうが早い。

```bash
ip route get 172.16.5.10
```

```
172.16.5.10 via 10.8.0.1 dev tun0 src 10.8.0.5
```

どの経路にマッチし、どの NIC から、どの送信元 IP で出るかが一発で分かる。複数 NIC のサーバーで「なぜか届かない」ときは、まずこれで「想定と違う NIC から出ていないか」を確認する。

なお `ifconfig` や `route` は非推奨の旧コマンドで、現行環境では入っていないことも多い。`ip` コマンド（iproute2）に統一して覚える。

## 経路の追加とフォワーディング

一時的な経路追加（再起動で消える。恒久化はネットワーク設定側で）：

```bash
sudo ip route add 192.168.100.0/24 via 10.0.1.254
```

また、Linux はデフォルトでは**自分宛でないパケットを転送しない**。サーバーをルーター/NAT ゲートウェイとして使うにはフォワーディングを有効化する必要がある：

```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

逆に言うと、ルーターにする意図のないサーバーでこれが 1 になっていたら、設定ミスか誰かが踏み台化した痕跡なので確認対象。
