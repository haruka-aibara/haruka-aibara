# ファイル転送

サーバーにファイルを送りたい・取ってきたい。手段は複数あって、「1回きりの小物」「巨大なディレクトリの同期」「URL からのダウンロード」で最適解が違う。使い分けの判断ごと覚えるのが早い。

## scp：1回きりの小物はこれ

SSH の上で動くコピー。SSH がつながる相手なら追加設定ゼロで使えるのが強み。

```bash
scp ./app.conf user@server:/etc/myapp/       # ローカル → リモート
scp user@server:/var/log/app.log ./          # リモート → ローカル
scp -r ./dist user@server:/opt/myapp/        # ディレクトリごと
```

`~/.ssh/config` のホスト定義（ProxyJump 含む）がそのまま効くので、`scp file prod-web:/tmp/` のように書ける。

## rsync：大きい・繰り返す・途中で切れるならこれ

rsync も SSH 上で動くが、**差分だけ転送する**のが決定的な違い。

```bash
rsync -avz ./website/ user@server:/var/www/html/
#      │└ z: 圧縮転送
#      └ a: パーミッション・タイムスタンプ等を保持しつつ再帰
rsync -avz --delete ./website/ user@server:/var/www/html/   # 送り元にないファイルを先方でも削除（完全同期）
```

使いどころの判断：

- **数GBの転送が途中で切れた** → rsync なら再実行すれば続きから。scp は最初からやり直し
- **毎日のバックアップ・デプロイ** → 変わったファイルだけ送るので2回目以降が桁違いに速い
- **`--dry-run`（-n）で「何が転送・削除されるか」を事前確認できる** → `--delete` を使うときは必ず一度 dry-run する

細かい罠として、送り元の末尾スラッシュで意味が変わる：`./website/` は「中身を」、`./website` は「ディレクトリごと」転送する。

## curl / wget：URL から取ってくる

サーバー間コピーではなく「Web 上のものを取得する」ならこちら。

```bash
curl -fsSLO https://example.com/release/app-v2.1.tar.gz
wget https://example.com/release/app-v2.1.tar.gz
```

ダウンロードした実行物をそのまま動かす前に、配布元が提供するチェックサムで検証する癖をつける（`sha256sum -c`）。`curl ... | bash` 形式のインストーラは中身を確認してから流す。

## 使わないもの・その他

- **FTP**: 平文で認証情報が流れるので新規に使う理由はない。既存システムの都合で必要なら SFTP（SSH ベース）へ
- **NFS**: 「転送」ではなく「マウントして共有」の世界。常時共有したい場合の選択肢
- クラウドでは S3 (`aws s3 sync`) など、オブジェクトストレージ経由のほうが権限管理・監査の面で筋がいい場面も多い
