# DHCP

サーバーの IP は誰が決めているのか。手で設定した覚えがないのに `ip addr` を打つと IP が付いている——それは DHCP がやっている。仕組みを知らなくても動くが、「IP が取れていない」「意図しない IP になった」「DNS 設定がなぜか書き換わる」といった問題は DHCP の理解なしには解けない。

## 何をしてくれるのか

DHCP（Dynamic Host Configuration Protocol）は、ネットワークに参加したマシンに **IP アドレス・サブネットマスク・デフォルトゲートウェイ・DNS サーバー**を自動配布する仕組み。クライアントがブロードキャストで「誰か設定ください」と叫び（DISCOVER）、DHCP サーバーが提案し（OFFER）、要求（REQUEST）・確定（ACK）で決まる。

配布された IP は「リース（貸与）」であって永続ではない。期限が来ると更新し、更新できなければ失効する。「昨日まで使えていた IP が変わった」のはリース更新のタイミングで別の IP が割り当てられたケース。

## クライアント側の調査

「IP が取れていない」症状はこう調べる：

```bash
ip addr show eth0                        # IP が付いているか。169.254.x.x なら DHCP 失敗のサイン
journalctl -u systemd-networkd -b       # または NetworkManager。DHCP のやりとりのログ
sudo dhclient -v eth0                    # 手動で DHCP を試行し、対話を目視する
```

`169.254.x.x`（リンクローカルアドレス）が付いているのは「DHCP サーバーから応答がなく、自分で勝手に付けた」状態のサイン。サーバー側か経路の問題と分かる。

`/etc/resolv.conf` の DNS 設定が「編集しても戻ってしまう」のも DHCP（とその情報を反映する systemd-resolved 等）の仕業。DNS を固定したい場合は resolv.conf を直接編集するのではなく、ネットワーク設定側（netplan、NetworkManager）で指定する。

## サーバーは固定、が原則

DHCP で配る側・配られる側の使い分けは明快で：

- **クライアント（人が使う端末、オートスケールするインスタンス）**: DHCP でよい
- **サーバー、ネットワーク機器、DNS/DHCP サーバー自身**: 固定 IP（または DHCP 予約 = MAC に対して常に同じ IP を返す設定）

サーバーの IP が変わると、それを参照している側が全部壊れるため。なお AWS の VPC では DHCP は AWS 管理のサービスとして最初から動いており（DHCP オプションセットで DNS などを制御）、自前で DHCP サーバーを立てるのは主にオンプレの話。

自前で立てる場合は `isc-dhcp-server`（後継は Kea）を入れて `/etc/dhcp/dhcpd.conf` に配布レンジや予約を書く。
