# サービスステータス確認

「Webにつながらない」「APIがタイムアウトする」と言われたとき、最初に確認すべきは「そもそもサービスプロセスが生きているか」。ログを漁る前にこれを見るだけで、調査の半分が終わることも多い。

## まず systemctl status

```bash
systemctl status nginx
```

```
● nginx.service - A high performance web server
     Loaded: loaded (/lib/systemd/system/nginx.service; enabled; preset: enabled)
     Active: active (running) since Sat 2026-07-11 09:00:12 JST; 3h 2min ago
   Main PID: 1234 (nginx)
```

見るポイントは2行だけ。

- **Active**: いまの状態。`active (running)` なら動いている。`failed` なら直近の起動か実行中に死んでいる。`inactive (dead)` は単に止まっている
- **Loaded** の `enabled/disabled`: ブート時に自動起動する設定かどうか。**「いま動いているか」とは別物**

この区別が実務では効いてくる。「再起動したらサービスが上がってこなかった」の原因は、たいてい `active` だけ確認して `disabled` のまま運用していたケース。逆に `enabled` でも手動で `stop` されていれば動いていない。

`failed` だった場合は status 出力の末尾に直近のログが数行出るので、そこから調査を始める（詳しくは [09-03_サービスログの確認](09-03_サービスログの確認.md)）。

## スクリプトから確認したいとき

監視スクリプトやデプロイ後のヘルスチェックで status の人間向け出力をパースするのは筋が悪い。専用のサブコマンドがある。

```bash
systemctl is-active nginx    # active / inactive / failed
systemctl is-enabled nginx   # enabled / disabled
```

終了コードも状態に対応している（active なら 0）ので、そのまま条件分岐に使える。

```bash
if ! systemctl is-active --quiet nginx; then
  echo "nginx is down" | notify-somewhere
fi
```

## 全体を俯瞰したいとき

「どれか落ちてないか」をまとめて見るなら failed だけ列挙するのが速い。

```bash
systemctl --failed
```

何も出なければ、systemd 管理下のサービスはすべて正常。サーバーにログインして最初に打つコマンドとして覚えておくと便利。
