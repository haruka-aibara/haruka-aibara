# マウント

ディスクを追加した、EBS ボリュームをアタッチした、NFS を使いたい——でもデバイスが見えるだけではファイルは読めない。Linux ではストレージをディレクトリツリーのどこかに「取り付ける」（マウントする）ことで初めてアクセスできるようになる。Windows のように D: ドライブが勝手に生えてくる世界ではない。

## 基本操作

```bash
sudo mount /dev/sdb1 /mnt     # /dev/sdb1 を /mnt に取り付け
df -h /mnt                    # 確認
sudo umount /mnt              # 取り外し
```

マウント先のディレクトリ（マウントポイント）はただの空ディレクトリでよい。`/mnt` は一時作業用の慣習的な場所で、恒久的に使うなら `/data` や `/var/lib/アプリ名` など用途に合った場所を掘る。

umount が「target is busy」で失敗するのは、誰かがその中のファイルを開いているかカレントディレクトリにしているとき。犯人は `lsof +f -- /mnt` や `fuser -vm /mnt` で特定できる（自分のシェルが cd している、が意外と多い）。

## 再起動すると消える問題と /etc/fstab

`mount` コマンドでのマウントはその場限りで、**再起動すると外れる**。恒久化するには `/etc/fstab` に書く。

```
# デバイス                                     マウント先  FS型  オプション        dump pass
UUID=1c24a3b2-...                              /data      ext4  defaults,nofail  0    2
```

デバイス名（`/dev/sdb1`）ではなく **UUID で書く**のが重要。デバイス名はディスクの認識順で変わることがあり（特にクラウドインスタンス）、名前がずれると別のディスクをマウントしたり起動に失敗したりする。UUID は `lsblk -f` か `blkid` で確認できる。

もう1つの事故防止が `nofail` オプション。fstab に書いたディスクが見つからないと、デフォルトでは**起動が emergency mode で止まる**。外れる可能性のあるデータディスクには nofail を付けておくと、そのディスク抜きで起動まで進んでくれる。

書いたら再起動前に検証する：

```bash
sudo mount -a       # fstab の内容を全部マウントしてみる（エラーが出ればここで分かる）
sudo findmnt --verify   # fstab の構文チェック
```

「fstab を編集 → 検証せずに再起動 → 起動しない」は定番の自爆パターンなので、`mount -a` の一手間を惜しまない。
