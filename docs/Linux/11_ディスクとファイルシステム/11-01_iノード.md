# iノード

`df` では空きがあるのに「No space left on device」でファイルが作れない——このパズルのような障害の答えが iノード。仕組みを知らないと絶対にたどり着けないので、ディスク周りでは最初に押さえておきたい概念。

## iノードとは

ファイルシステム上の各ファイル・ディレクトリには、**iノード（index node）** というメタデータの入れ物が1つ割り当てられている。中身はサイズ・所有者・パーミッション・タイムスタンプ・データブロックの位置など。

重要なのは、**ファイル名は iノードに含まれない**こと。ファイル名は「ディレクトリが持つ、名前→iノード番号の対応表」に過ぎない。ファイルの実体は iノードのほうで、名前はそこへの参照でしかない。

```bash
ls -i memo.txt        # iノード番号を表示
stat memo.txt         # iノードの中身（メタデータ）を表示
```

この「名前と実体の分離」が分かると、いくつかの挙動が腑に落ちる：

- **ハードリンク**は「同じ iノードに別の名前を付ける」操作。`ls -l` の2列目（リンク数）は、その iノードを指す名前の数
- **削除中のファイルをプロセスが掴んでいると容量が減らない**のは、名前を消してもプロセスが iノードを参照している間は実体が解放されないから（`lsof | grep deleted` で見つかる）
- `mv` が同一ファイルシステム内なら一瞬で終わるのは、データを動かさず対応表を書き換えているだけだから

## 冒頭の障害：iノード枯渇

iノードの数はファイルシステム作成時に固定で確保される。つまり**ディスク容量とは別に「作れるファイル数」に上限がある**。小さいファイルを大量に作るワークロード（セッションファイル、キャッシュ、メールキュー、ログの細切れ）では、容量より先に iノードが尽きることがある。

```bash
df -h     # 容量はまだ 60%
df -i     # IUse% が 100% ← 犯人
```

`df -i` で iノード使用率を確認できる。枯渇していたら、大量の小ファイルがどこにあるかを探して消す：

```bash
# ディレクトリごとのファイル数を概算して多い順に
sudo du --inodes -d1 /var | sort -n | tail
```

「No space left on device が出たら `df -h` と `df -i` の両方を見る」——これだけ覚えて帰ってもらえれば、この記事の目的は達成している。
