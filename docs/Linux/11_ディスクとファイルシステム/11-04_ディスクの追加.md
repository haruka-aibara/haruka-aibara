# ディスクの追加

ディスクを増設した、クラウドでボリュームをアタッチした。でも OS からは「生のブロックデバイス」が見えるだけで、そのままでは使えない。使えるようにするまでの流れは決まっていて、**認識確認 → （パーティション）→ ファイルシステム作成 → マウント** の一本道。

## 1. 認識されているか確認

```bash
lsblk -f
```

```
NAME    FSTYPE  UUID     MOUNTPOINT
sda
├─sda1  ext4    ...      /
sdb                               ← 追加したディスク。FSTYPE が空
```

FSTYPE も MOUNTPOINT も空の `sdb` が、まだ何もされていない新しいディスク。**ここで対象デバイスを絶対に取り違えないこと**。この後の手順は既存データを完全に消すので、サイズや既存パーティションの有無で慎重に確認する。

## 2. パーティションを切る（省略可）

```bash
sudo fdisk /dev/sdb    # 対話式。n で新規作成 → w で書き込み
```

ディスク全体を1つの用途で使うなら、パーティションを切らずディスク全体（`/dev/sdb`）に直接ファイルシステムを作る運用も普通にある（クラウドのデータボリュームでは切らないほうが後のサイズ拡張が楽）。切った場合は以降 `/dev/sdb1` を対象にする。

## 3. ファイルシステムを作る

```bash
sudo mkfs.ext4 /dev/sdb1
```

これがいわゆる「フォーマット」。既存データがあれば消えるので、mkfs は人生で一番タイプミスしたくないコマンドのひとつ。

## 4. マウントして恒久化

```bash
sudo mkdir /data
sudo mount /dev/sdb1 /data
```

再起動後も維持するには `/etc/fstab` に UUID で追記する（詳細と事故防止オプションは [11-03_マウント](11-03_マウント.md)）。

```bash
sudo blkid /dev/sdb1     # UUID を確認して fstab に書く
sudo mount -a            # 再起動前に fstab を検証
```

## クラウドでの注意点

AWS の Nitro インスタンスでは、アタッチした EBS ボリュームが `/dev/sdb` ではなく `/dev/nvme1n1` のような NVMe デバイス名で見える。デバイス名は当てにせず、`lsblk` で「FSTYPE が空の新入り」を探すという上記の手順がそのまま通用する。また、あとからボリュームを拡張した場合は `growpart` + `resize2fs`（XFS なら `xfs_growfs`）でファイルシステム側を追従させる。
