# スワップ

メモリ2GBの小さいインスタンスでビルドを走らせたら OOM Killer にプロセスを殺された。RAM を増やすほどではないが、瞬間的なメモリ不足を吸収したい——そういうときの保険がスワップ。物理メモリが逼迫したとき、使われていないメモリページをディスクに退避して RAM を空ける仕組み。

## 現状確認

```bash
free -h
swapon --show
```

`free -h` の Swap 行が `0B` なら未設定。クラウドのインスタンス（Amazon Linux、Ubuntu の AMI など）はスワップなしがデフォルトのことが多い。

## スワップファイルを作る

昔は専用パーティションを切ったが、いまはファイルで作るのが手軽で主流。サイズ変更も簡単。

```bash
sudo fallocate -l 2G /swapfile      # 2GB のファイルを確保
sudo chmod 600 /swapfile            # root 以外読めないように（メモリ内容が書かれるため必須）
sudo mkswap /swapfile               # スワップ領域として初期化
sudo swapon /swapfile               # 有効化
```

`chmod 600` は飾りではない。スワップにはプロセスのメモリ内容——パスワードや秘密鍵を含み得る——がそのまま書き出されるので、一般ユーザーに読ませてはいけない。

再起動後も有効にするには `/etc/fstab` に追記：

```
/swapfile none swap sw 0 0
```

## スワップは「遅い保険」と理解する

ディスクは RAM より桁違いに遅い。スワップが常用される状態（スワップイン・アウトが恒常的に発生する状態）は、性能劣化と引き換えに延命しているだけで、根本解決は RAM 増設かアプリのメモリ削減。

- **スワップの役割**: 一時的なスパイクを OOM Killer による即死から守る／アイドルなページを追い出して RAM をキャッシュに回す
- **スワップで解決しないこと**: 恒常的なメモリ不足

「どれくらい積極的にスワップするか」は `vm.swappiness`（0〜200、既定60）で調整できる。データベースサーバーなどでは低め（10 前後）にして「本当に困るまでスワップしない」設定にすることが多い。

```bash
sudo sysctl vm.swappiness=10                      # その場で変更
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-swap.conf   # 恒久化
```

なお Kubernetes ノードは伝統的にスワップ無効が前提（メモリ制限の挙動を予測可能にするため）だったように、環境によっては「作らない」が正解のこともある。プラットフォームの流儀を先に確認する。
