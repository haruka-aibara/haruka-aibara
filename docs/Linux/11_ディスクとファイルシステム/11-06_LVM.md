# LVM

「/var が満杯になったのでディスクを足したい。でもパーティションを切り直すのは怖い」。物理パーティションの世界では、サイズ変更は隣接領域の空きに縛られる窮屈な作業になる。この硬直性を解消するのが LVM（Logical Volume Manager）——物理ディスクとファイルシステムの間に「自由に切り貼りできる論理層」を挟む仕組み。

## 3層構造だけ覚える

- **PV（Physical Volume）**: LVM に差し出す物理ディスク／パーティション
- **VG（Volume Group）**: PV を束ねた「ストレージのプール」。ここに容量が貯まる
- **LV（Logical Volume）**: プールから切り出した論理的な区画。この上にファイルシステムを作る

物理ディスクの境界は VG が吸収してくれるので、LV は「複数ディスクにまたがるボリューム」でも「あとから拡張するボリューム」でも自由に作れる。RHEL 系はインストーラのデフォルトが LVM 構成なので、意識せず使っていることも多い（`lsblk` で `lvm` と出るやつ）。

## 一連の流れ

```bash
sudo pvcreate /dev/sdb                  # ディスクを PV 化
sudo vgcreate data-vg /dev/sdb          # VG（プール）を作る
sudo lvcreate -n app-lv -L 50G data-vg  # プールから 50GB 切り出す
sudo mkfs.ext4 /dev/data-vg/app-lv      # あとは普通のデバイスと同じ
sudo mount /dev/data-vg/app-lv /data
```

現状確認は `pvs` / `vgs` / `lvs`（それぞれの一覧）。

## 本領発揮：無停止で拡張する

冒頭の「/var が満杯」への LVM の答えはこう。ディスクを1本足して、プールに追加して、LV を膨らませる。**アンマウント不要・サービス無停止**でできる。

```bash
sudo pvcreate /dev/sdc
sudo vgextend data-vg /dev/sdc                    # プールに容量追加
sudo lvextend -r -L +30G /dev/data-vg/app-lv      # LV拡張。-r でFSも同時に拡張
```

`-r`（`--resizefs`）を付ければファイルシステムの拡張まで一発でやってくれる。逆方向（縮小）は ext4 ならオフラインで可能だが XFS は不可、かつ失敗するとデータを失うので、実務では「拡張は気軽に、縮小は作り直しで」と考えておくのが安全。

## スナップショット

LV は同じ VG 内の空き容量を使ってスナップショット（その瞬間の静止画像）を取れる。パッケージの大型アップデートやデータ移行の前に取っておき、失敗したら巻き戻す、という使い方ができる。

```bash
sudo lvcreate -s -n app-snap -L 10G /dev/data-vg/app-lv
```

クラウドでは EBS スナップショットなどプラットフォーム側の機能を使うことが多いが、オンプレや「ファイルシステムレベルで一貫した瞬間を切り取りたい」場面では今も現役。
