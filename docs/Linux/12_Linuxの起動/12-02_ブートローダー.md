# ブートローダー

カーネルを更新して再起動したら起動しなくなった。あるいは起動時に `grub>` というプロンプトで止まった。普段は存在すら意識しないブートローダーは、トラブルが起きたときだけ突然主役になる。最低限の仕組みを知っておくと、その日に詰まない。

## 電源ONからログインまでの流れ

1. **ファームウェア（UEFI/BIOS）** がハードウェアを初期化し、ブートローダーを探して実行
2. **ブートローダー（GRUB）** がカーネルと initramfs（初期RAMディスク）をメモリにロードして起動
3. **カーネル** がドライバを読み込み、ルートファイルシステムをマウント
4. **systemd**（PID 1）がサービスを順に起動してログイン可能に

ブートローダーの仕事は「どのカーネルを、どのオプションで起動するか」の選択と受け渡し。Linux では **GRUB**（GRUB 2）がほぼ標準（歴史的には LILO というシンプルな先代がいた。今のクラウド環境では、より軽量な systemd-boot を使うディストリビューションもある）。

## 設定変更の作法：grub.cfg を直接編集しない

GRUB の実体設定は `/boot/grub/grub.cfg`（RHEL系は `/boot/grub2/grub.cfg`）だが、これは**自動生成ファイルなので直接編集しない**。編集するのは `/etc/default/grub` で、その後に生成コマンドを実行する。

```bash
sudo vi /etc/default/grub        # 例: GRUB_CMDLINE_LINUX にカーネルパラメータ追加
sudo update-grub                 # Debian/Ubuntu（grub.cfg を再生成）
sudo grub2-mkconfig -o /boot/grub2/grub.cfg   # RHEL 系
```

カーネルパラメータの追加（cgroup の有効化、コンソール出力先の変更など）はこの手順でやる。

## トラブル時に効く知識

**カーネル更新後に起動しない**：GRUB のメニューには古いカーネルも残っている。起動時にメニューから1つ前のカーネル（Advanced options 配下）を選べば、とりあえず前の環境で起動できる。「カーネル更新は古いカーネルを消さずに残す」のはこのための保険。

**root パスワードを忘れた／緊急シェルが欲しい**：GRUB メニューで `e` を押してカーネル行に `systemd.unit=rescue.target` などを一時追加して起動する、という手が使える。逆に言うと、**物理コンソールに触れる人は GRUB 経由でシステムを掌握できる**ということでもある。データセンター外にある機器やラップトップでは、GRUB にパスワードを設定する・ディスクを暗号化する、がこのリスクへの対処になる。

**クラウドでは**：EC2 などではブート画面に触れないので、起動不能時はシリアルコンソール（EC2 Serial Console）を使うか、ボリュームを別インスタンスにアタッチして修復するのが定石。
