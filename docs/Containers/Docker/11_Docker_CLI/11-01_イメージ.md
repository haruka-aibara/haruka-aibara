# Docker CLI：イメージ操作

イメージ操作コマンドの一覧整理。pull・ls・rm の基本は [04-03-01](../04_Dockerの基本/04-03_Dockerのコマンド/04-03-01_extra_イメージの管理（pull、ls、rm）.md) で扱っているので、ここでは**調査・掃除・移送**という運用寄りの操作をまとめる。

## 調査：このイメージは何者か

```bash
docker image ls                       # 手元のイメージ一覧（サイズ・タグ）
docker image inspect nginx:latest     # メタデータ全部（ENV、ExposedPorts、Entrypoint…）
docker image history nginx:latest     # レイヤーごとの生成コマンドとサイズ
```

使いどころ：

- **「このイメージ、起動したら何が実行されるのか」** → `inspect` で `Config.Entrypoint` と `Config.Cmd` を見る。ドキュメントのないイメージの挙動確認はここから
- **「なぜこんなにデカいのか」** → `history` でサイズの大きいレイヤーを特定。どの RUN/COPY が犯人か一目で分かる
- **「秘密が焼き込まれていないか」** → `history` で ENV や COPY の内容を確認（[10-02_イメージセキュリティ](../10_コンテナセキュリティ/10-02_イメージセキュリティ.md)）

`inspect` の出力は `--format` で絞れる：

```bash
docker image inspect --format '{{.Config.Entrypoint}}' myapp
```

## 掃除：ディスクを取り戻す

イメージは黙って溜まり、CI サーバーや開発機のディスクを圧迫する。

```bash
docker system df          # 何がどれだけディスクを食っているかの内訳
docker image prune        # dangling（タグなし）イメージだけ削除
docker image prune -a     # どのコンテナからも使われていないイメージを全削除
```

`prune -a` は「あとで使うつもりだった」イメージも消すので、中身を分かって打つ。CI ランナーでは定期実行（cron）に入れておくのが定番。

## 移送：レジストリを経由できないとき

エアギャップ環境やレジストリ障害時に、イメージをファイルとして持ち運ぶ：

```bash
docker image save myapp:1.4.2 -o myapp.tar    # イメージ → tar
docker image load -i myapp.tar                 # tar → イメージ
```

似た名前の `docker export`（コンテナの FS を tar 化。レイヤー情報が飛ぶ）とは別物なので注意。イメージの移送は save/load。
