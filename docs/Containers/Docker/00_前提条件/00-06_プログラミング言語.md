# 前提知識：プログラミング言語

「コンテナ化する対象」がないと Docker の学習は素振りで終わる。何か1つ、自分でアプリを書ける言語があると、Docker の各機能が「自分のアプリをどう本番に運ぶか」という具体的な問題になる。

## 言語ごとにコンテナ化の考えどころが違う

どの言語でもいいが、言語によって Dockerfile で悩むポイントが変わる。逆に言うと、自分の言語の「型」を1つ覚えれば応用が利く。

- **Python**: 依存を `requirements.txt`（や uv、poetry）でどう固定するか。ベースイメージは `python:3.x-slim` が定番
- **Node.js**: `node_modules` をレイヤーキャッシュにどう乗せるか（`package*.json` だけ先に COPY する定型）
- **Go / Rust**: ビルドと実行を分けるマルチステージビルドの効果が最大級。最終イメージを `distroless` や `scratch` にできる
- **Java**: JVM のヒープ設定とコンテナのメモリ制限の関係という固有の論点がある

共通するのは「**依存関係のインストールとアプリ本体のコピーをレイヤーとして分ける**」という発想で、これはどの言語でも同じ。

## このリポジトリでは

Python の学習コンテンツが `Programming Language/Python/` 配下にある。Docker の題材としても Python アプリ（Flask や FastAPI の小さな API）は手頃で、[09_コンテナの実行](../09_コンテナの実行/) の compose 実践とも組み合わせやすい。
