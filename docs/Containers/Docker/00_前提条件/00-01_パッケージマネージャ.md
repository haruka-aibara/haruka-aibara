# 前提知識：パッケージマネージャ

Docker を学び始めると、パッケージマネージャの知識が2箇所で必要になる。**Docker 自体のインストール**（apt リポジトリの追加）と、**Dockerfile の中**（`RUN apt-get install ...`）。特に後者は毎日書くことになるので、前提として押さえておく。

## Dockerfile の中で毎回書くことになる

イメージのビルドは「ベースイメージに、パッケージマネージャで必要なものを足していく」作業が中心になる。

```dockerfile
FROM ubuntu:24.04
RUN apt-get update && apt-get install -y --no-install-recommends \
    curl \
    ca-certificates \
 && rm -rf /var/lib/apt/lists/*
```

この定型には全部理由がある：

- `apt-get update` と `install` を**同じ RUN で**：別レイヤーに分けると古いインデックスがキャッシュされ、install が404で壊れる（レイヤーキャッシュの罠）
- `--no-install-recommends`：推奨パッケージを入れずイメージを小さく保つ
- `rm -rf /var/lib/apt/lists/*`：インデックスをレイヤーに焼き込まない

ベースイメージが Alpine なら `apk add --no-cache`、Red Hat 系（UBI）なら `dnf` と、**ベースイメージのディストリビューションによって使うコマンドが変わる**。エラーの原因が「Alpine に apt はない」だった、は初学者の定番。
