# このリポジトリの運用ルール

`AGENTS.md` に書ききらない、置き場所とメモの残し方。

## docs/ の置き場所

`docs/` 直下はフラットで、1階層目はトピック名そのもの（`Terraform/`, `Cyber Attacks/`）。
`Provisioning/Terraform/` のような分類ディレクトリは作らない。置き場所を記憶に頼る羽目になるため。

- `docs/` 直下のディレクトリ名は英語、単語区切りはスペース。2階層目以降は日本語でよい
- 記事が1本でもトピック名のディレクトリに置く。`docs/` 直下に記事ファイルを直接置かない
- 思いついたアイデアは `docs/Ideas/YYYY-MM-DD-名前.md` にフラットに置き、1行目に `tags:` を書く。1500 文字以内の入口に留め、詳細は該当トピックのディレクトリに書いてリンクする。育ったら該当トピックへ移し、やらないと決めたら消す。数が増えたら年別ディレクトリに分ける
- 目次は `docs/index.html`。GitHub API でツリーを動的に取得するので手を入れる必要はない

## 残すものはリポジトリ内に書く

devcontainer なので `~/.claude/` 配下は再起動で消える。会話をまたぐ情報はリポジトリ内に書く。

| 内容 | 書く場所 |
|---|---|
| 記事の書き方 | `.claude/skills/article-writing/` |
| 何がどこにあるか（1行） | `docs/reference/既存コンテンツ.md` |
| 好み・判断軸・表記ルール | `docs/reference/ユーザーの好み.md` |
| Terraform / CI の運用 | `README.md` |
| 置き場所・メモ運用 | このファイル |
| 索引と鉄則 | `AGENTS.md`（増やさない。10行程度に保つ） |

ツール別の指示ファイル（`CLAUDE.md` / `GEMINI.md`）は作らない。特定ツールだけに効く注意も
そのツール名を添えて該当ファイルに書く。`AGENTS.md` を自動で読まないツールは、転送用ファイルを
足すのではなくツール側の設定で `AGENTS.md` を指す。

## スキル

**リポジトリルートの `.claude/skills/`** に置く。サブディレクトリでは読み込まれない。
`AGENTS.md` をルートに置いているのも同じ理由。

- `article-writing`: 記事（HTML / markdown）を書くときのルール一式
- `story-breakdown`: ストーリーをサブタスクと基準線に分解する

## やらないこと

- 英語で書く
- 過度な装飾やフォーマット統一の強制
