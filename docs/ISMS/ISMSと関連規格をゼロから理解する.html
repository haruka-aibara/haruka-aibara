ISMS と関連規格をゼロから理解する

27000、27001、27002、27014、BS 7799-1、BS 7799-2。似た番号の正体を、系譜と役割で 1 回だけ整理する。

何が分からないのか

ISMS の勉強を始めると、番号が一斉に出てくる。JIS Q 27000、JIS Q 27001、JIS Q 27002、JIS Q 27014、そして BS 7799-1、BS 7799-2、ISO/IEC 27002。どれも「情報セキュリティの規格」としか説明されず、番号の違いが何の違いなのか分からないまま暗記することになる。

この違いは、実は 2 つの軸しかない。どこが出した文書か（BS＝英国、ISO/IEC＝国際、JIS＝日本）と、何を書いた文書か（満たすべき要求事項か、実装の手引か、用語の定義か）。系譜を一度たどれば、あとは位置で思い出せる。

規格の系譜：もとは 1 つの英国規格

出発点は英国規格の BS 7799。1995 年の BS 7799-1 が「こうやるとよい」というベストプラクティス集、1999 年の BS 7799-2 が「認証を受けるならこれを満たすこと」という要求事項。この 2 本立てが、そのまま今の 27002 と 27001 になっている。

BS 7799-1 は ISO/IEC 17799 を経て ISO/IEC 27002 に、BS 7799-2 は ISO/IEC 27001 になった。それを日本語化して日本産業規格にしたのが JIS Q 27001 / JIS Q 27002。つまり JIS Q 27001 と ISO/IEC 27001 は中身が同じで、違うのは発行元だけ。

27001 と 27002 の役割の違い

ISMS そのものは何を回す枠組みか

ISMS（情報セキュリティマネジメントシステム）は、製品でもツールでもなく組織の仕組みのこと。守るべき情報資産を洗い出し、リスクを評価し、対策を決めて実行し、うまくいっているか点検して直す——この PDCA を回し続けることが ISMS で、JIS Q 27001 はその回し方を要求事項として書いている。

「セキュリティ製品を導入すること」ではないので、審査で見られるのも製品ではなく運用の記録になる。

ポリシの 3 階層と残留リスク

ISMS で作る文書は、抽象度で 3 段に分かれる。

階層何を書くか例
基本方針
（ポリシ）		経営者が示す方針。なぜ守るのか、誰が責任を持つか「当社は顧客情報の保護を経営上の責務と位置づける」
対策基準
（スタンダード）		方針を実現するために守るべきルール「パスワードは 12 文字以上とする」
実施手順
（プロシージャ）		現場が実際に動くための具体的な手順「アカウント発行の申請フローと承認者」

上ほど抽象的で滅多に変わらず、下ほど具体的で頻繁に更新される。基本方針だけ立派で実施手順がない、という状態は ISMS として成立しない。

残留リスク

対策を打ってもリスクはゼロにならない。対策後に残るものを残留リスクと呼ぶ。重要なのは、これを「受け入れる」と決めるのが現場ではなく経営者だという点。経営陣が残留リスクを承認し、ISMS の状況を監督する——その関係を定めているのが JIS Q 27014（情報セキュリティガバナンス）。

認証を与える側の登場人物

認証を受ける企業のほかに、3 つの登場人物がいる。

  • 認証機関（審査登録機関）：企業を審査して ISMS 認証を与える。企業が直接契約する相手はここ。
  • 認定機関：その認証機関に審査する資格があるかを認定する。日本の ISMS 認証制度では ISMS-AC（情報マネジメントシステム認定センター）が担う。制度を立ち上げ運営してきたのが JIPDEC（日本情報経済社会推進協会）で、認定業務は現在 ISMS-AC に引き継がれている。
  • 審査員：実際に現場を見る人。認証機関に所属し、要員認証機関（JRCA など）に資格を登録している。

「認証する側も認定されている」という入れ子構造なのは、認証機関を誰も見ていなければ認証が買えるものになってしまうから。

3 種類の審査は、いつ来るか

3 つの違いは、ひとことで言えば目的が違う。認証審査は「認証してよいか」、維持審査は「認証を維持してよいか」、更新審査は「もう 3 年続けてよいか」。頻度と範囲の違いはこの目的から出てくる。
