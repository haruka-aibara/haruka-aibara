# 非同期処理（asyncio）

「1000個の URL の死活チェック、1件ずつ回すと30分かかる」。ほぼ全時間が応答待ちなのだから、待ちを重ねられれば数十秒で終わるはず——この「**大量の I/O 待ちを1スレッドで重ねる**」ための仕組みが asyncio。スレッド（数十並行が現実的）よりずっと軽く、数千・数万の並行に耐える。

## 基本形：async def・await・gather

```python
import asyncio
import httpx

async def check(client: httpx.AsyncClient, url: str) -> tuple[str, int]:
    r = await client.get(url, timeout=5)      # 待ちの間、他のチェックが進む
    return url, r.status_code

async def main():
    async with httpx.AsyncClient() as client:
        tasks = [check(client, u) for u in urls]
        return await asyncio.gather(*tasks)    # 全部を並行実行して結果を集める

results = asyncio.run(main())
```

部品は3つだけ：

- `async def`：コルーチン（中断・再開できる関数）の定義
- `await`：「ここで待つので他をどうぞ」という譲りポイント
- `asyncio.run()` / `gather()`：イベントループの起動と、並行実行の束ね

イベントループは**1スレッド**で全コルーチンを回す。「await に到達したら次のコルーチンへ」を高速に繰り返しているだけで、並列ではなく協調的な並行。

## 2大ルール

**1. async の世界に同期 I/O を持ち込まない**

`await` できない処理（`requests.get`、`time.sleep`）はイベントループごと凍結させ、全並行が止まる。ライブラリは async 対応品（httpx、aiofiles、asyncpg…）で揃え、`time.sleep` は `asyncio.sleep` に。どうしても同期しかなければ `await asyncio.to_thread(sync_func)` でスレッドに逃がす。

**2. 並行数は絞る**

1000並行は書けてしまうが、相手サーバーには 1000 同時接続＝実質的な攻撃になる（自分側のリソースも枯れる）。セマフォで上限を入れるのが行儀：

```python
sem = asyncio.Semaphore(20)

async def check_limited(client, url):
    async with sem:                      # 同時実行を20に制限
        return await check(client, url)
```

自作のスキャナや監視スクリプトを書くとき、この1枚があるかどうかが「調査ツール」と「DoS」の分かれ目になる。

## 使いどころの整理

- **向いている**：大量の HTTP リクエスト、多数の同時接続を捌くサーバー（[12-08_非同期型](../12_フレームワークを学ぶ/12-08_非同期型.md)）、WebSocket
- **向いていない**：CPU バウンド（1スレッドなので並列にならない → [13-01_マルチプロセッシング](13-01_マルチプロセッシング.md)）、数本程度の並行（スレッドで十分、async 対応ライブラリへの縛りがない分楽）

「スレッドの代替」ではなく「**I/O 待ちの数が多いときの専用装備**」と捉えるのが実務的。
