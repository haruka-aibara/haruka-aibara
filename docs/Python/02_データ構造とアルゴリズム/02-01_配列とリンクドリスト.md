# 配列とリンクドリスト

「リストの先頭に要素を足し続けたらスクリプトが異様に遅い」——Python の `list` は名前に反して**配列**であり、先頭への挿入が苦手。データ構造の知識は抽象論ではなく、この手の「なぜか遅い」を説明し、正しい道具に置き換えるための語彙になる。

## 配列：連続したメモリ、末尾は速く、先頭は遅い

配列は要素をメモリ上に**連続して**並べる。Python の `list` はこの方式（正確には参照の配列）。

- **添字アクセスが O(1)**：位置が計算で出るので即座に届く。`items[10000]` は一瞬
- **末尾への追加 `append` は O(1)**：空きに置くだけ（余裕がなくなったらまとめて拡張）
- **先頭への挿入・削除は O(n)**：`insert(0, x)` や `pop(0)` は、**全要素を1つずつずらす**。10万要素あれば10万回の移動

冒頭の「遅いスクリプト」の正体は `pop(0)` をループで回していた、が定番。n 回繰り返せば O(n²) になり、データが増えた途端に破綻する。

## リンクドリスト：鎖のつながり、先頭は速く、添字は遅い

リンクドリストは各要素が「値と、次の要素への参照」を持つ鎖。メモリ上の連続性がない代わりに：

- **先頭・末尾への追加削除が O(1)**：鎖のつなぎ替えだけ
- **添字アクセスが O(n)**：n 番目に行くには先頭から辿るしかない

Python でこの性質が欲しいときは、自作するのではなく標準ライブラリの **`collections.deque`**（両端キュー。実装は連結ブロック）を使う：

```python
from collections import deque

queue = deque()
queue.append(job)        # 末尾に追加 O(1)
job = queue.popleft()    # 先頭から取り出し O(1) ← list.pop(0) の O(n) と対照的
```

## 使い分けの実際

| やりたいこと | 正解 |
|---|---|
| 添字でランダムアクセス、末尾に追加 | `list` |
| 先頭からも取り出す（FIFO キュー、直近N件のバッファ） | `deque`（`maxlen` 付きが便利） |
| 「含まれているか」の判定が主 | そもそも `set` / `dict`（[02-02](02-02_ハッシュテーブル.md)） |

面接やアルゴリズム問題以外で生のリンクドリストを書くことはまずないが、「list の先頭操作は高い」「deque という代替がある」の2点は日常のコードの性能に直結する。
