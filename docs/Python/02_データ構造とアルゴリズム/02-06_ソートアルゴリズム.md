# ソートアルゴリズム

Python でソートアルゴリズムを自作することは実務ではない——`sorted()` が優秀すぎるから。それでも学ぶ意味は2つある：**計算量の感覚を持つこと**（「この処理、データが10倍になったらどうなる？」に答える力）と、**`sorted()` を正しく使いこなすこと**。

## まず結論：組み込みを使う

```python
sorted(items)                          # 新しいリストを返す
items.sort()                           # インプレース（省メモリ）
sorted(users, key=lambda u: u.age)     # キー指定
sorted(users, key=attrgetter("dept", "age"))   # 複数キー
```

Python のソートは **Timsort**（マージソート＋挿入ソートのハイブリッド、Python のために発明されて今や Java 等も採用）。最悪 O(n log n)、**実データにありがちな「部分的にソート済み」で圧倒的に速い**、そして**安定**（同順位の元の順序を保つ）。

安定であることは実務で効く。「部署でソート→その中で年齢順」は、安定だからこそ**2回に分けてソートしても正しい**：

```python
users.sort(key=attrgetter("age"))     # 先に副次キー
users.sort(key=attrgetter("dept"))    # 後に主キー（同部署内は age 順が保たれる）
```

## 計算量の感覚：O(n²) と O(n log n) の壁

古典アルゴリズムを知る価値は、この壁の体感にある。

| アルゴリズム | 平均 | 特徴 |
|---|---|---|
| バブル/挿入/選択ソート | **O(n²)** | 実装が簡単。n=10万で約100億回比較→現実的に死ぬ |
| マージソート | O(n log n) | 安定。追加メモリが要る |
| クイックソート | O(n log n) | 高速だが最悪 O(n²)・不安定 |
| Timsort（Python標準） | O(n log n) | 安定＋実データに強い |

n=100万のとき、n² は1兆、n log n は約2000万。**5万倍**の差。ソートに限らず、「ループの中で in や pop(0) を使って O(n²) を作ってしまう」（[02-01](02-01_配列とリンクドリスト.md)、[02-02](02-02_ハッシュテーブル.md)）ことへの嗅覚が、この表から得る本当の収穫。

## 全部ソートしない、という選択肢

- **上位N件だけ**：`heapq.nlargest(10, items)` — 全ソート O(n log n) に対して O(n log 10)
- **最小・最大だけ**：`min()` / `max()` — O(n)
- **ソート済みに1件足す**：`bisect.insort()`（[02-04](02-04_二分探索木.md)）

「ソートしてから先頭を取る」と書きそうになったら、本当に全体の順序が必要かを一度疑う。
