# 再帰

ディレクトリを再帰的に走査する、入れ子の JSON を舐める、組織図を辿る——**構造自体が入れ子になっているデータ**の処理は、再帰で書くと構造とコードが一致して素直になる。逆に言うと、入れ子構造以外にあえて再帰を使う場面は Python では少ない。

## 基本形：自分を呼ぶ関数

再帰は「基底ケース（もう分解できない最小の場合）」と「再帰ケース（一段小さくして自分に任せる）」の2部構成。**基底ケースを最初に書く**のが作法で、忘れると無限再帰する。

```python
def total_size(path: Path) -> int:
    if path.is_file():                 # 基底ケース：ファイルならサイズを返すだけ
        return path.stat().st_size
    return sum(total_size(child) for child in path.iterdir())   # 再帰ケース
```

入れ子 JSON から特定キーを全部集める、のような処理も同じ型：

```python
def find_keys(data, key):
    results = []
    if isinstance(data, dict):
        for k, v in data.items():
            if k == key:
                results.append(v)
            results.extend(find_keys(v, key))
    elif isinstance(data, list):
        for item in data:
            results.extend(find_keys(item, key))
    return results
```

IAM ポリシーや CloudFormation テンプレートのような深い入れ子の設定を検査するスクリプトは、実務でこの型をよく使う。

## RecursionError：Python 特有の天井

Python は再帰の深さに上限がある（デフォルト約1000。関数呼び出しの都度スタックに積むため）。深い入れ子や大きなデータで `RecursionError: maximum recursion depth exceeded` に当たったら：

- **ループ＋自前スタックに書き換える**のが正攻法。再帰は機械的にループへ変換できる：

```python
def total_size_iter(root: Path) -> int:
    stack, total = [root], 0
    while stack:
        path = stack.pop()
        if path.is_file():
            total += path.stat().st_size
        else:
            stack.extend(path.iterdir())
    return total
```

- `sys.setrecursionlimit()` で上限を上げるのは応急処置。構造の深さが入力次第（＝攻撃者が制御できる場合も含む）なら、上限をいくら上げても足りない。**外部入力の深い入れ子で再帰を落とす**のは DoS の古典なので、パーサ的な処理では深さ制限を明示するのが堅い

なお他言語にある末尾呼び出し最適化（末尾再帰をループに自動変換する仕組み）を CPython は意図的に持たない。「Python の再帰は深さ1000まで」と覚えておく。

## 使う・使わないの判断

- **使う**：木構造・入れ子データの走査、分割統治（クイックソート等）——構造が再帰的なもの
- **使わない**：単純な繰り返し（ループでよい）、深さが入力に依存して無制限になりうるもの
