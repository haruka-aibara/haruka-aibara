# ヒープ、スタック、キュー

「取り出す順番」に名前を付けたのがこの3つ。ジョブを積んで順に処理する、直近のものから巻き戻す、優先度の高いものから捌く——どれも日常のプログラムに出てくる要求で、Python では3つとも標準ライブラリで済む。

## スタック：後入れ先出し（LIFO）

最後に積んだものを最初に取り出す。「戻る」操作の実装（undo、ブラウザバック、木構造の探索）はすべてスタック。

```python
stack = []
stack.append(page)    # push
page = stack.pop()    # pop（最後に積んだものが出る）
```

Python では **list がそのままスタック**（append/pop は両方 O(1)）。関数呼び出しの管理（コールスタック）もスタックで、再帰が深すぎると `RecursionError` になるのはこのスタックが尽きるから（[02-05_再帰](02-05_再帰.md)）。

## キュー：先入れ先出し（FIFO）

先に入れたものを先に取り出す。処理待ちの列——ジョブキュー、リクエストのバッファ、幅優先探索。

```python
from collections import deque

queue = deque()
queue.append(job)         # enqueue
job = queue.popleft()     # dequeue（先に入れたものが出る）
```

list で `pop(0)` すると O(n) なので、**キューは deque を使う**（[02-01](02-01_配列とリンクドリスト.md)）。なおスレッド間の受け渡しにはロック付きの `queue.Queue`、プロセス間なら `multiprocessing.Queue` と、並行処理の文脈では専用品がある。

## ヒープ：常に「最小（優先度最高）」が先頭

積んだ順でも逆順でもなく、**優先度順**に取り出す。タスクスケジューラ（次に実行すべきものはどれか）、上位N件の抽出、ダイクストラ法など。

```python
import heapq

heap = []
heapq.heappush(heap, (priority, task))   # O(log n)
priority, task = heapq.heappop(heap)     # 最小 priority のものが出る O(log n)
```

全体をソートし続ける（毎回 O(n log n)）のではなく、「先頭が最小」だけを保証する木構造で持つのがミソ。**「上位10件だけ欲しい」に全件ソートは過剰**で、`heapq.nlargest(10, items)` が正解になる、というのが実務での典型的な使いどころ。

## まとめ：選び方

| 取り出したい順 | 構造 | Python |
|---|---|---|
| 新しいものから（巻き戻し） | スタック | `list` |
| 古いものから（処理待ち行列） | キュー | `collections.deque` |
| 優先度の高いものから | ヒープ | `heapq` |
