DNS 水責め攻撃とマルチベクトル型 DDoS

「攻撃元をブロックすればいい」が通じないように作られた DDoS。

何が問題なのか

DDoS 対応の定石は「攻撃元を特定して落とす」「攻撃の種類を見て対応する緩和策を当てる」。この 2 つを意図的に外しにいく攻撃が存在する。片方は攻撃元が正規のサーバになるもの、もう片方は1 つの緩和策では足りないようにするもの。

DNS 水責め攻撃（ランダムサブドメイン攻撃）

標的は Web サーバではなく、ドメインの権威 DNS サーバ。ここが落ちれば、Web もメールもまとめて名前解決できなくなる。

攻撃者はボットネットを使い、世界中のキャッシュ DNS サーバ（特にアクセス制御されていないオープンリゾルバ）に対して a8f3k2xq.example.com のような実在しないランダムなサブドメインを問い合わせさせる。

被害は権威サーバ側だけではない。踏み台にされたキャッシュ DNS も、応答が返らない未解決クエリを大量に抱え込み、そのリゾルバを使う無関係な利用者の名前解決まで遅くなる／失敗する。両側がじわじわ溺れるので「水責め」と呼ばれる。

立場やること
権威 DNS を運用する側Anycast で受け口を分散する。マネージド DNS（Amazon Route 53 など）に寄せて規模で吸収させるのが現実的。自前運用なら RRL（Response Rate Limiting）を設定
キャッシュ DNS を運用する側オープンリゾルバにしない（問い合わせ元を自組織内に限定）。同一ドメイン宛の未解決クエリ数に上限を設ける

マルチベクトル型 DDoS

単一の手法なら、たいてい対応する緩和策が 1 つある。SYN Flood には SYN Cookie、UDP 増幅には上流でのフィルタ、HTTP Flood には WAF のレート制限。

マルチベクトル型はこれらを同時に、あるいは切り替えながら仕掛ける。

対策の考え方は、手法ごとに個別の防御を積み上げるのではなく層で持つこと。L3/L4 は自社回線の手前（CDN・DDoS 緩和サービス）、L7 は WAF、DNS は DNS 側の設計。そのうえで手順を先に決めておく——誰が緩和サービスの防御モードを上げるか、誰が上流の ISP に連絡するか。攻撃を受けている最中に手順を考えるのは無理がある。

提案するときの言い方

「DDoS 対策は攻撃を受けてから買うと間に合いません。契約と連絡経路、切り替え手順まで含めて平常時に一度通しで確認しておくところまでが対策です」——製品の導入ではなく、手順の有無として説明するほうが通りやすい。
