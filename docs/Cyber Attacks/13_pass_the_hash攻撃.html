pass the hash 攻撃 — ハッシュそのものが鍵になる

「パスワードはハッシュ化してあるから盗まれても平気」が通じない場面がある。

ハッシュを盗めば、パスワードを知らなくてもログインできる

Windows の NTLM 認証では、パスワードそのものをネットワークに流さない。代わりにパスワードのハッシュを鍵として、サーバから来たチャレンジに応答を返す。パスワードが流れないという点では安全な設計だ。

ところがこれは裏返すと、認証に必要なのはパスワードではなくハッシュだということでもある。侵入した端末のメモリからハッシュを取り出せれば、元のパスワードが分からなくても、そのハッシュを使って他のサーバにログインできてしまう。

怖いのは1台で終わらないこと

この攻撃が問題になるのは横展開のしやすさによる。全端末のローカル管理者パスワードが同じだと、1台の侵害がそのまま全台の侵害になる。1台目で取り出したハッシュが、そのまま他の全端末で通ってしまうからだ。

対策は運用側の話が中心になる。

  • 端末ごとにローカル管理者パスワードを変える。使い回しをやめるだけで横展開が止まる。自動で個別化・定期変更する仕組みがある。
  • 認証情報をメモリから隔離する。Windows の Credential Guard は、ハッシュやチケットを通常の OS から切り離した領域に置き、取り出せなくする。
  • 強い権限のアカウントを、末端の端末にログインさせない。ドメイン管理者で一般端末に入ると、その端末が侵害された時点で管理者の認証情報ごと奪われる。

提案するときの言い方。「ハッシュを盗まれる」では危機感が伝わりにくい。「1台がマルウェアに感染したときに、それが全社に広がるか1台で止まるかが、ローカル管理者パスワードの使い回しで決まる」と言い換えると、投資判断の話として通じやすい。
