ポートスキャンの4種（TCP / SYN / FIN / NULL）

攻撃はいきなり侵入から始まらない。最初に来るのは「どのポートが開いているか」の調査。

なぜ応答の違いで開閉が分かるのか

TCP は接続時に SYN → SYN/ACK → ACK の3回のやりとりをする。このとき、開いているポートと閉じているポートでは返ってくるものが違う。閉じていれば RST（接続拒否）が返る。この差を外から順に確かめていくのがポートスキャンで、種類の違いは「どこまでやりとりをするか」の違いだ。

種類送るもの開いている閉じている特徴
TCP（コネクト）3ウェイハンドシェイクを完走接続成立RST結果は確実。接続ログに残る
SYN（ステルス／ハーフオープン）SYN のみ。応答が来たら RST で打ち切るSYN/ACKRST成立させないのでログに残りにくい
FINFIN フラグだけ応答なしRST「応答なし＝開」と逆読みする
NULLフラグを全部 0応答なしRST同上

知っておくこと2つ

実行に必要な権限が違う。①は OS の通常の接続機能をそのまま使うので特別な権限が要らない。②③は TCP ヘッダを自分で組み立てて送るため管理者権限が必要になる。

FIN / NULL は相手の OS 次第で当てにならない。「開いているポートは無反応」は TCP の仕様どおりに実装した OS の挙動で、Windows など一部の OS は開いていても RST を返す。この場合、スキャン結果は全ポート閉じているように見える。逆にこの反応の違いは、相手の OS を推測する材料にもなる。
