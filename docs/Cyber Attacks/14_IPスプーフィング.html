IP スプーフィング — 送信元アドレスは自己申告

パケットの送信元 IP は差出人が自分で書く欄でしかない。偽ってもそのまま届く。

送信元 IP は誰も確かめていない

IP パケットの送信元アドレスは、送る側がヘッダに書き込む値にすぎない。途中の経路が「本当にその住所から来たのか」を検証する仕組みは、標準では動いていない。だから送信元を別の IP に偽って送りつけることができる。これが IP スプーフィング。

使われ方は主に2つある。1つは送信元 IP を根拠にしたアクセス制御の回避。「社内ネットワークの IP なら許可」といった判定を騙す。もう1つが、より実害の大きい反射・増幅型の DDoS だ。

TCP では乗っ取りまでは難しい

TCP は接続時に3回のやりとりをする。送信元 IP を偽ると、サーバからの応答は偽った側の IP に返ってしまい、攻撃者の手元には届かない。応答に含まれる値を使って続きを組み立てられないため、そのまま通信を乗っ取るのは難しい。

だから IP スプーフィングが効くのは、応答を受け取る必要がない攻撃——UDP を使った反射・増幅型の DDoS や、接続を張らせるだけで消耗させる攻撃が中心になる。

対策はネットワーク側で行う

受け取る側で「この送信元は偽物だ」と判定するのは難しい。有効なのは出ていくパケットを送り出す側で止めることで、自分の管理下から出るパケットの送信元 IP を検査し、そのネットワークに存在しないアドレスのものを落とす（送信元フィルタリング、BCP 38）。各組織・各 ISP が自分の出口で実施して初めて、全体として効いてくる種類の対策になる。
