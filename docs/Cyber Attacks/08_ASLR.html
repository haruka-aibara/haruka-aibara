ASLR — 番地を毎回変えて狙わせない

攻撃には「どこへ飛ばすか」の正確な番地が要る。起動ごとに配置を変えれば、その前提が崩れる。

攻撃コードは番地を決め打ちしている

リターンアドレスを書き換える攻撃も、既存コードの断片を繋ぐ ROP も、「この番地に飛べば目的の処理がある」と決め打ちできることが前提になっている。同じ実行ファイルなら誰の環境でも同じ番地に置かれる——この性質を利用して、攻撃コードは番地を埋め込んで作られる。

ASLR（Address Space Layout Randomization）は、実行ファイル・共有ライブラリ・スタック・ヒープの配置先を起動のたびにランダムに変える。攻撃者は狙う番地を事前に決められなくなる。

効かなくなる場合

  • 実行ファイル本体が PIE でビルドされていないと、ライブラリだけがランダム化され、本体は固定の番地に置かれる。そこに使える断片があれば足がかりにされる。
  • 番地が漏れると無効になる。別の脆弱性でメモリの中身を読み出せる場合、その値からランダム化のずれを逆算されてしまう。ASLR は単体ではなく、DEP や SSP と重ねて初めて意味を持つ。

Linux では /proc/sys/kernel/randomize_va_space（既定 2）で状態を確認できる。無効化されたまま運用されていないか、たまに見ておくとよい。
