Web ビーコン — 開いた瞬間に伝わるもの

1×1 の透明画像 1 枚で、「いつ・どこから・誰が開いたか」が相手のログに残る。

何が問題なのか

「怪しいメールのリンクは踏まない」までは常識になっている。では開くだけなら安全か、というとそうではない。HTML メールの本文に外部サーバの画像が 1 枚置いてあると、メールクライアントがその画像を取りに行った時点で、置いた側のサーバにアクセス記録が残る。リンクを踏まなくても、最後まで読まなくても、表示された瞬間に伝わる。

これが Web ビーコン（Web バグ、トラッキングピクセル）。1×1 ピクセルの透明画像がよく使われるのは、見えないから。もともとは Web サイトのアクセス解析の仕組みで、いまもメールマーケティングの開封率測定に普通に使われている。攻撃側から見ると、これはそのアドレスが生きていて、実際に人が読んでいることの確認手段になる。

仕組み

ログに残るものそこから分かること
アクセス日時・回数いつ開いたか、何度読み返したか
送信元 IP アドレスおおよその地域、組織のネットワークかどうか
User-Agent使っているメールクライアントと OS・端末
URL の IDどの宛先が開いたか（＝生きているアドレス）

Web サイトでも同じ手口

メールの例で説明したが、同じものが Web ページにも埋め込まれる。複数のサイトが同じ事業者のビーコンを貼っていると、その事業者だけが横断的に閲覧を観測できる。

読まれずに済ませる

  • 画像の自動読み込みをオフにする：最も効く。主要なメールクライアントは既定でブロックし、「画像を表示」ボタンを出す。ここを押すかどうかが分かれ目。
  • 心当たりのないメールでは押さない：押した瞬間に、そのアドレスが「生きている」と確定する。
  • ブラウザ側はトラッキング防止機能：Safari の ITP、Firefox の ETP など。既定で有効になっているものが多い。

セキュリティ視点

Web ビーコンは、それ自体では何も壊さない。効いてくるのはその後で、サイバーキルチェーンでいえば偵察の段階にあたる。攻撃者はばらまいたメールの開封記録から、生きているアドレス・読んでいる時間帯・使っているクライアントとバージョンを絞り込み、次に送る標的型メールの精度を上げる。

「開いただけだから大丈夫」は成り立たない

インシデント対応で「リンクは踏んでいないので影響なし」と報告されることがあるが、開封の事実が相手に渡っている以上、そのアドレスは次の標的リストに残る。同じ相手から続報が来る前提で扱う。

提案するときの言い方——「開封しただけでは実害はありません。ただし、そのアドレスが実在して読まれていることは相手に伝わっています。同じ送信元からの次のメールを警戒する必要があります」。
