セッションフィクセーション — ID を盗まずに使わせる

セッション ID を盗むのが難しいなら、自分が知っている ID を相手に使わせればいい、という発想の攻撃。

盗まなくても乗っ取れてしまう

Web アプリでは、ログイン後の「この人は本人だ」という判断をセッション ID で行う。だから攻撃者はセッション ID を盗もうとする——というのが素直な発想だが、盗む必要はない。

攻撃者があらかじめ手に入れた ID を、利用者にそのまま使わせてログインさせる。ログインが成功した時点で、その ID は「認証済み」として扱われる。攻撃者は最初から ID を知っているので、そのまま本人としてアクセスできてしまう。

対策は「ログイン成功時に ID を発行し直す」

③の時点でサイトが新しいセッション ID を発行し直せば、攻撃者が握っている ABC は認証済みにならず、④が成立しない。これが対策の中心で、他の細かい話はすべて補助だと考えていい。主要なフレームワークにはこの再発行の機能が用意されている。

合わせて、次の2つで②の仕込み自体を難しくできる。

  • URL パラメータで渡されたセッション ID を採用しない。Cookie で扱う。
  • Cookie に HttpOnly / Secure を付ける。スクリプトからの読み書きと、暗号化されていない通信での送出を止める。
