DEP / NX — データ置き場のコードを実行させない

送り込んだコードにジャンプされても、そこが実行不可なら動かない。

入力として送り込まれたコードが、なぜ動いてしまうのか

古典的なバッファオーバーフロー攻撃は2段構えになっている。まず入力データとして機械語のコード（シェルコード）を送り込み、次にリターンアドレスをそのデータの番地に書き換えて、そこへ飛ばせる。うまくいけば攻撃者のコードがプログラムの権限で動く。

成立している前提は「データを置いた場所を、CPU がコードとしても実行してくれる」こと。DEP（Data Execution Prevention。CPU 側の機能名から NX ビット、Linux では W^X とも呼ばれる）は、この前提を壊す。データ用の領域には「実行不可」の印を付けておき、そこへ飛んだ時点で CPU が拒否する。

DEP だけでは足りない。新しいコードを送り込めないなら、すでに実行可能な場所にあるコードの断片を繋いで目的を果たす、という迂回手法（ROP）がある。この組み立てには各断片の正確な番地が必要になるので、番地を毎回変える ASLR と組み合わせて初めて実用的な防御になる。
