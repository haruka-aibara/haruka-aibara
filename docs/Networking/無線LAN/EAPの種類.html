EAP の種類

EAP-TLS / EAP-TTLS / PEAP / EAP-MD5 / EAP-POTP。違いは「証明書を誰に配るか」に集約される。

まず「トンネルを張るかどうか」で分かれる

認証のやりとりを保護しないと、パスワードの情報がそのまま電波に乗る。そこで多くの方式は、先にサーバ証明書を使って暗号トンネルを張り、その中でパスワードを確認する。この構図が分かると個々の名前は整理できる。

方式端末に証明書位置づけ
EAP-TLS必要最も強い。配布と失効管理の手間を許容できるなら第一候補
EAP-TTLS不要サーバ証明書でトンネルを張り、中で任意の方式を使う
PEAP不要TTLS とほぼ同じ発想。企業でよく使われる
EAP-MD5—保護がなく無線では使えない。使わない
EAP-POTP—ワンタイムパスワードのトークンを使う方式

証明書を配らない方式では、端末側の設定が肝心。「どの認証サーバ証明書を信じるか」を端末に設定していないと、同じ名前を名乗る偽 AP にパスワードを渡してしまう。PEAP／TTLS を使うなら、証明書の検証を有効にした状態で配布する。
