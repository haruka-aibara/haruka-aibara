VXLAN

別のデータセンタにある VM を、同じ LAN にいるかのように扱いたい。L2 を L3 の上に載せる技術。

VLAN では足りなくなった 2 つの理由

ネットワークを論理的に分ける手段として VLAN がある。しかし仮想化・クラウドの規模では 2 つの壁にぶつかる。

  • 数が足りない — VLAN ID は 12 ビットで最大 4094 個。テナントごとに割り当てるマルチテナント環境ではすぐ枯渇する
  • ルータを越えられない — VLAN は L2 の仕組みなので、L3 で分かれた別拠点にまたがれない。VM を別データセンタへライブマイグレーションすると IP が変わってしまう

VXLAN はこれを、イーサネットフレームを丸ごと UDP パケットの中に詰めて運ぶことで解決する。外側から見れば普通の IP 通信なので、ルータを何台越えても届く。中身を取り出せば元のフレームなので、両端の VM からは同じ L2 セグメントに見える。

導入時に必ず出てくる MTU の問題

カプセル化すると外側のヘッダ分だけパケットが大きくなる。VXLAN では外側 Ether + IP + UDP + VXLAN で 50 バイト増える。

VM が MTU 1500 のつもりで 1500 バイトのフレームを出すと、包んだ結果 1550 バイトになり、物理ネットワークの MTU 1500 を超えて分割か破棄が起きる。「小さい通信は通るのに、大きいデータの転送だけ固まる」という症状の典型的な原因がこれ。

対策は 2 つ。物理ネットワーク側をジャンボフレーム（MTU 9000 など）にするか、VM 側の MTU を 1450 に下げる。データセンタ内なら前者を選べることが多い。

セキュリティ上の注意：VXLAN 自体に暗号化も認証もない。UDP 4789 に到達できる相手なら、任意の VNI を名乗ってフレームを注入できる。オーバーレイの下にある物理ネットワークを信頼できる範囲に閉じ、外部から 4789 に届かないようにするのが前提になる。拠点間をインターネット経由で結ぶ場合は IPsec を併用する。
