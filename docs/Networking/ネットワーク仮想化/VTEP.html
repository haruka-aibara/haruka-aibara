VTEP

VXLAN で「包む人」と「開ける人」。トンネルの出入口にあたる機能。

誰かが包まないとトンネルは成立しない

VXLAN は元のイーサネットフレームを UDP に詰めて運ぶ。ではその詰め込みと取り出しは誰がやるのか。VM 自身はそんなことを知らないし、知らないままでよい——それが VXLAN の利点だからだ。

この役割を担うのが VTEP（VXLAN Tunnel End Point）。トンネルの端点で、次の 2 つを行う。

  • 送信側 — VM から来たフレームに VXLAN・UDP・IP ヘッダを付けて、相手側 VTEP の IP 宛てに送る
  • 受信側 — 届いた UDP パケットからヘッダを剥がし、中のフレームを本来の宛先 VM へ渡す

対応表をどうやって埋めるか

宛先 VM がどの VTEP の配下にいるかを、VTEP は最初は知らない。埋め方に 2 通りある。

方式やり方特徴
マルチキャスト（フラッド&ラーン）宛先不明のフレームを全 VTEP に配り、応答から学習する設定は単純だが、物理ネットワークがマルチキャスト対応である必要がある
コントロールプレーン（EVPN）BGP EVPN で VTEP どうしが MAC 情報を事前に交換するフラッディングが不要。現在の主流

クラウドや大規模データセンタでは後者が使われる。マルチキャストは IGMP の設定が要り、そもそもクラウドでは使えないことが多いため。

調査時の注意：VTEP を挟むと、物理ネットワーク上のパケットキャプチャに見えるのは外側の IP アドレスだけになる。「どの VM が通信しているか」は VXLAN ヘッダの内側を展開しないと分からない。Wireshark は VXLAN をデコードできるので、UDP 4789 として認識させれば中身まで追える。フローログだけで調査しようとすると VTEP 間の通信しか見えず、行き詰まる。
