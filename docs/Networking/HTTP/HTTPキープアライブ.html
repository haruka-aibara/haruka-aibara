HTTP キープアライブ

ページ 1 枚に画像や CSS が何十個。そのたびに TCP 接続を張り直していたら、待ち時間のほとんどが「挨拶のやり直し」になる。

1 回の接続を使い回す

HTTP/1.0 の基本動作は「1 リクエストごとに TCP 接続を作り、応答を返したら切る」だった。TCP は使い始める前に 3 ウェイハンドシェイクの往復が必要なので、リソースが増えるほど本題と関係ない往復時間が積み上がる。HTTPS ならさらに TLS ハンドシェイクも毎回やり直しになる。

キープアライブ（持続的接続）は、一度張った TCP 接続を切らずに次のリクエストにも使い回す仕組み。HTTP/1.1 からはこれがデフォルトになり、切りたいときだけ Connection: close を送る。
