プロトコルアナライザ

「アプリのログには何も出ていないのに、つながらない」。そのとき実際に何が流れているかを見る道具。

ログでは分からないことがある

クライアントは「タイムアウトしました」と言い、サーバのログには何も残っていない。この状態で切り分けられることは少ない。リクエストがサーバまで届いていないのか、届いたが応答が返っていないのか、返ったが途中で消えたのか——どれなのかが分からないからだ。

プロトコルアナライザ（パケットキャプチャツール）は、ネットワークを流れるパケットをそのまま拾って中身を解析する。上の 3 つは実際にキャプチャを見れば一目で区別がつく。代表的なものが Wireshark、コマンドラインなら tcpdump。

使うときに踏んではいけないところ

パケットキャプチャは平文で流れているものが全部見える。認証情報・個人情報・セッションクッキーが含まれうる。攻撃者にとっては強力な盗聴ツールでもあり、実際に スニファ として攻撃側で使われる。

  • 取得の許可を得る — 他人の通信の傍受は、社内でも手続きなしに行ってよいものではない。対象・期間・目的を決めてから取る
  • キャプチャファイルを機密として扱う — .pcap は生データそのもの。共有フォルダに置きっぱなしにしない
  • フィルタで範囲を絞る — tcpdump host 10.0.1.5 and port 443 のように、必要な通信だけを取る。証跡としても説明しやすくなる

トリガーを意識する：キャプチャが必要になる場面は、たいてい「障害が起きてから」。ところが事象が再現しないと取れない。だから重要な通信経路では、フローログ（VPC フローログなど）を常時取っておくほうが先に効く。フローログで「通信が届いているか」までは分かり、中身が要るときだけキャプチャに降りる、という順序になる。
