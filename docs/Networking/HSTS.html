HSTS

https のサイトでも、最初の 1 回だけは平文で始まってしまう。その 1 回を消すための仕組み。

リダイレクトしていれば安全、ではない

サイトを https 化して「http で来たら https へリダイレクト」を設定した。それでも、ユーザーがアドレス欄に example.com と打ったときの最初のリクエストは平文で飛ぶ。同じ Wi-Fi にいる攻撃者はここに割り込み、ブラウザには http のまま応答して、自分だけがサーバと https で話す（SSL ストリッピング）。ユーザーは鍵マークがないことに気づかないまま入力する。

やることはヘッダを 1 行返すだけ

https の応答にこのヘッダを付ける。

Strict-Transport-Security: max-age=31536000; includeSubDomains

受け取ったブラウザは「このドメインへは今後 1 年間（31536000 秒）必ず https で接続する」と覚える。includeSubDomains を付けるとサブドメインにも効く。

初回だけは守れない。ヘッダを受け取る前の 1 回目は普通の http のままなので、上の攻撃が成立する余地が残る。これを埋めるのが preload——ブラウザに最初から焼き込まれた「常に https」ドメインの一覧に登録する仕組み。登録すると解除に時間がかかるので、https 化が完全に終わってから申請する。
