IP マスカレード

グローバル IP が 1 つしかないのに、社内の 100 台が同時にインターネットへ出られる理由。

アドレスが足りないので使い回す

IPv4 のグローバルアドレスは有限で、契約でもらえるのはたいてい 1 個か数個。しかし社内には端末が何十台もある。全台にグローバル IP を配るのは不可能。

そこで社内ではプライベートアドレス（192.168.x.x など）を使い、外に出るときだけ 1 つのグローバル IP に書き換える。これが NAT の考え方。

ただし単純な NAT（1 対 1 の変換）では、同時に外に出られるのは 1 台だけ。複数台を同時に通すために、IP アドレスに加えてポート番号も一緒に書き換えて区別するのが IP マスカレード（NAPT / PAT）。

外から中への通信は原則できない

テーブルは内側から通信を始めたときに作られる。外から突然来たパケットには対応する行がないので、ルータはどこへ渡せばよいか分からず破棄する。

結果として、IP マスカレードは意図せず簡易的なファイアウォールとして働く。ただしこれをセキュリティ対策と呼ぶのは危うい。内側から出た通信の戻りは全部通るので、端末がマルウェアに感染して外部へ接続を始めれば、そのまま通信路が開く。

外部からアクセスさせたいサーバがある場合は、ポートフォワーディング（静的 NAT）で「このポートに来たらこの内部 IP へ」という行をあらかじめ作っておく。

クラウドでの対応物：AWS のプライベートサブネットから外部へ出るときの NAT ゲートウェイがこれにあたる。動作原理が同じなので「外からは入れない、中から出た戻りは通る」という性質もそのまま。
なお NAT を挟むと、サーバ側のアクセスログには全端末が同じ IP に見える。インシデント調査で「どの端末が」を追うには、NAT 側の変換ログ（VPC フローログなど）が別に要る。
