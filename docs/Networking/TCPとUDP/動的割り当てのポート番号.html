動的割り当てのポート番号

サーバのポートは 443 と決まっている。ではクライアント側のポート番号は誰が決めているのか。

通信には「両側」のポート番号が要る

ブラウザで Web サイトを見るとき、宛先ポートが 443 なのは分かる。しかし応答を返してもらうには、クライアント側にも受け取り口としてのポート番号が必要。しかもタブを 3 つ開けば 3 本の通信が同時に走るので、全部違う番号でなければ区別できない。

この番号は OS が接続のたびに空いているものを自動で選ぶ。これが動的割り当てのポート番号（エフェメラルポート）。通信が終われば解放され、また別の接続で再利用される。

実際の範囲は IANA の定義どおりではない

IANA は動的ポートを 49152〜65535 と定めているが、実際の OS はこれに従っていないことが多い。1024 番以降の任意のポートを使う実装が普通で、確認や変更ができる。

OS既定の範囲確認方法
Linux32768〜60999sysctl net.ipv4.ip_local_port_range
Windows49152〜65535netsh int ipv4 show dynamicport tcp
macOS49152〜65535sysctl net.inet.ip.portrange

Linux の範囲が 1024 番台まで下がっていないのは、そこに登録済みポートを使うサービスがあるため。ただし「49152 未満は使われない」と前提を置くと、Linux では成り立たない。

ハマりどころ：短時間に大量の接続を開閉するサーバでは、この範囲を使い切って新規接続に失敗することがある（ポート枯渇）。
特に IP マスカレード や NAT ゲートウェイの背後では、配下の全端末が 1 つのグローバル IP のポート範囲を共有するので枯渇しやすい。AWS の NAT ゲートウェイで ErrorPortAllocation メトリクスを監視するのはこのため。対策はコネクションの再利用（キープアライブ）か、接続元 IP を増やすこと。
