TCP ヘッダ

IP が「どのホストへ」を担当するなら、TCP は「そのホストのどのアプリへ」と「確実に届いたか」を担当する。

ホストに着いただけでは足りない

1 台のサーバでは Web も SSH もメールも動いている。IP アドレスだけでは、届いたパケットをどのアプリに渡せばよいか分からない。また、パケットが順不同で届いたり欠けたりしたときに、それを直す情報もどこかに要る。

この 2 つを担うのが TCP ヘッダ。ポート番号でアプリを特定し、シーケンス番号と確認応答番号でデータの順序と欠落を管理する。

ウィンドウサイズ — 相手の処理能力に合わせる

1 パケット送るたびに確認応答を待っていたら、往復時間の分だけ待ち時間が積み上がる。かといって受信側の処理が追いつかない量を送れば、あふれて捨てられる。

そこで受信側が「いま受け取れる残り容量」をウィンドウサイズとして毎回申告し、送信側はその範囲内なら確認応答を待たずに続けて送れる。受信側が詰まってくると値が小さくなり、送信が自然に絞られる。
