UPnP — 誰も申請していないのにポートが開いている

機器が自分でルータに穴を開ける仕組み。便利さと引き換えに何を渡しているか。

何が問題なのか

NAT の内側にいる端末は、外から接続を受けられない。ゲーム機や P2P アプリ、一部のビデオ会議は「外から着信を受ける」必要があるので、本来ならルータでポート開放の設定をしなければならない。ところが実際には、何も設定していないのに動く。

誰がポートを開けたのか。アプリ自身が、ルータに「このポートを自分宛に転送してくれ」と頼んで開けさせている。この頼み方の仕組みが UPnP（Universal Plug and Play）、正確にはその中の IGD（Internet Gateway Device）という機能。つまりLAN 内の端末が、管理者を通さずに NAT の穴を作れる。

3 ステップで「探して・調べて・命令する」

その前提が崩れると何が起きるか

「LAN 内にいれば信頼できる」は、LAN 内の 1 台がマルウェアに感染した瞬間に崩れる。マルウェアは同じ手順を踏むだけで、自分宛のポートを外向きに開ける。境界のファイアウォールを迂回するのではなく、正規の機能で穴を開けさせるので、ルータのログにも異常として残らない。

どうするか

  • 業務ネットワークのルータでは UPnP を無効にする。外部からの着信が必要なら、申請を受けて管理者が明示的にポート開放する。何が開いているかを管理者が把握できる状態を保つ、というだけの話。
  • WAN 側の UDP 1900 を閉じる。外向けに UPnP/SSDP が応答していないか、外部から確認する。
  • 家庭・小規模拠点では止められないこともある。その場合はルータの管理画面でポートマッピング一覧を定期的に見て、身に覚えのない転送設定がないかを確認する。

「UPnP を切ると何が動かなくなるか」を先に確認する

一律に無効化すると、ゲーム機・IP カメラ・一部の会議システムが繋がらなくなって差し戻される。無効化を提案するときは、その拠点で UPnP に依存している機器を洗い出し、代替（固定のポート開放、あるいは外向き通信だけで成立するクラウド経由の構成）とセットで出す。「危ないので切る」だけでは通らない。
