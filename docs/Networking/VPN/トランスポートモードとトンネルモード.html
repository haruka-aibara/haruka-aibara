トランスポートモードとトンネルモード

IPsec を設定するとき最初に迫られる分岐。何が隠れるかが変わる。

何が問題なのか

IPsec の設定画面を開くと、暗号アルゴリズムより先に「モード」を選ばされる。トランスポートモードかトンネルモードか。どちらも中身は暗号化するが、元の IP ヘッダを残すかどうかが違う。ここを間違えると、拠点間をプライベート IP のまま通す構成が作れない。

トランスポートモード

元の IP ヘッダを残し、その中身（TCP ヘッダから先）だけを保護する。送信元と宛先の IP はそのまま見える。通信するホスト自身が IPsec を喋る構成で使う。

トンネルモード

元の IP パケットを丸ごと「データ」として包み、外側に新しい IP ヘッダを付ける。外側のヘッダに書かれるのは VPN 装置同士の IP なので、経路上からは誰と誰が通信しているかも分からない。中に包まれた IP アドレスはプライベートアドレスでよく、そのまま相手拠点まで届く。

どちらを選ぶか

実務ではほぼトンネルモード。拠点間 VPN もクラウドとの接続も、端末側に手を入れずプライベート IP のまま通したいからで、それができるのはトンネルモードだけ。トランスポートモードは、サーバ同士が直接 IPsec で話す限定的な構成で使う。

トンネルモードを選んだら MTU を確認する

外側 IP ヘッダ＋ESP のぶん、実データに使えるサイズが数十バイト減る。「疎通はするのに大きい通信だけ固まる」ときは、まずここを疑う。ルータ側で TCP MSS を書き換える設定（MSS クランプ）を入れるのが定石。
