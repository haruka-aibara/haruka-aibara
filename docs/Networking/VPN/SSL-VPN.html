SSL-VPN

出先から社内に入りたい。でも IPsec は通らない——を解決する方式。

何が問題なのか

IPsec の VPN は拠点間なら問題ない。両端に自分たちの装置があり、必要なポートを開けられるからだ。ところが、出張先のホテルや客先、公衆 Wi-Fi から社員のノート PC を繋ごうとすると急に詰まる。IPsec は UDP 500 と ESP（または UDP 4500）を通す必要があるが、外のネットワークでそこが塞がっていても、こちらからは何もできない。

一方、どこでもまず開いているポートがある——HTTPS の TCP 443。Web が見える場所ならどこからでも繋がる。TLS の上に VPN を作ってしまおう、というのが SSL-VPN。

3つの方式 — どこまで届くかが違う

「SSL-VPN」と一括りにされるが、実現方法は3種類あり、社内のどこまで届くかが変わる。

方式端末に要るもの使えるもの
リバースプロキシブラウザだけ社内 Web アプリのみ
ポートフォワーディング小さなエージェント指定した TCP アプリ
L2 フォワーディングクライアントソフトほぼ全部（IPsec に近い）

セキュリティ視点 — 装置そのものが標的になる

SSL-VPN 装置は、社内に入るための入口をインターネットに向けて常時公開している。しかも認証を通れば境界の内側に直接入れる。つまりこの装置の脆弱性は、そのまま社内ネットワークへの侵入経路になる。ランサムウェア被害の初期侵入経路として、VPN 機器の既知脆弱性の悪用は毎年上位に来ている。

「TLS だから安全」ではない

TLS が守っているのは経路であって、装置そのものではない。守るべきは次の3点。

  • ファームウェアを速やかに当てる：脆弱性が公開されてから悪用が始まるまでが短い
  • 多要素認証を必須にする：漏洩済みの ID とパスワードだけで入れる状態を残さない
  • 棚卸しする：退職者・終了した委託先のアカウントが残っていないか。VPN のアカウントは消し忘れの定番

優先度を通すときの言い方——「VPN 装置のパッチは、社内サーバのパッチとは重みが違う。ここが破られると認証を経ずに社内ネットワークまで到達される」。
