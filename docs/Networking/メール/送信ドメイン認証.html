送信ドメイン認証

SMTP では差出人を自由に名乗れる。フィッシングメールが実在の会社を名乗れてしまう根本原因はここにある。「本当にそのドメインから来たのか」を受信側が検証する仕組みの総称。

メールには差出人が 2 つある

SMTP は差出人の申告を一切検証しない。しかも差出人は 2 か所にあり、それぞれ別々に、自由に書ける。

  • エンベロープ From — SMTP のやりとり（MAIL FROM）で申告される配送用の差出人。エラー返送先。受信者には通常見えない
  • ヘッダ From — メール本文のヘッダに書かれた差出人。メールソフトに表示されるのはこちら

3 つの仕組みで裏を取る

送信ドメイン認証は、受信サーバが DNS を使って差出人の裏を取る仕組みで、役割の違う 3 つを組み合わせる。

仕組み確かめること方法
SPF正規のサーバ（IP）から送られたか送信元 IP を DNS の申告と照合
DKIM正規の送信者が署名し、改ざんされていないか電子署名を DNS の公開鍵で検証
DMARC表示されるヘッダ From と整合するか・失格をどう扱うかポリシーを DNS で公開

SPF と DKIM が個別の検証手段、DMARC がそれらを「受信者に見えるヘッダ From」に結び付けて全体を束ねる、という関係になっている。
