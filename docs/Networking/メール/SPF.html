SPF

「うちのドメインのメールを送っていいサーバは、この IP だけ」と DNS で公開しておく。受信側はそれと照合するだけで、無関係なサーバからのなりすましを弾ける。

送信元 IP と DNS の申告を突き合わせる

差出人ドメインは自由に名乗れても、どの IP アドレスから接続してきたかは偽装しにくい（TCP で会話が成立している相手なので）。SPF はここに目を付けた仕組み。

ドメインの管理者は、正規の送信サーバの IP アドレスを DNS の TXT レコード（SPF レコード）として公開しておく。受信サーバは、届いたメールのエンベロープ From のドメインの SPF レコードを引き、実際の送信元 IP がそこに含まれるか確認する。

SPF はメール転送に弱い。メーリングリストや転送サービスを経由すると送信元 IP が転送サーバのものに変わり、正規のメールでも fail になる。また検証するのはエンベロープ From であって、受信者に表示されるヘッダ From ではない。この 2 つの穴を埋めるのが DKIM と DMARC。
