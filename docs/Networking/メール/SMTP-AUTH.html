SMTP-AUTH（SMTP Authentication）

SMTP は名乗るだけで送れる設計だった。送信の入口にユーザ認証を付け足したのが SMTP-AUTH。

送信の入口で本人確認する

認証のない SMTP サーバは、スパム送信者にとって格好の踏み台になる。POP before SMTP のような回避策を経て、SMTP のプロトコル拡張として正式に認証が入った。

ポイントは、認証を行うのが利用者からの投稿（サブミッション）を受け付ける入口だという点。メールソフトはサブミッションポート 587 番に接続し、AUTH コマンドでユーザ名とパスワードを確認してもらってから送信する。サーバ間の転送（25 番）は従来どおり認証なしで動く——見知らぬサーバからのメールも受け取るのがメールの仕組みだから、そこには認証を入れられない。
