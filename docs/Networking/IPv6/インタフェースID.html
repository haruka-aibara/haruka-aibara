インタフェース ID

IPv6 アドレスの後半 64 ビット。DHCP サーバがなくても機器が自分で決められる部分。

「サーバなしでアドレスが決まる」の後半部分

IPv6 では、ルータが「このネットワークのプレフィックスは 2001:db8:1::/64 です」と広告するだけで端末がアドレスを持てる。前半 64 ビットはルータからもらえるが、後半 64 ビットは端末が自分で決める。この後半がインタフェース ID。

同じセグメント内で重複しなければよいので、決め方は複数ある。

なぜランダム生成が標準になったか

EUI-64 方式には決定的な問題がある。MAC アドレスは機器に固定されているので、カフェでも自宅でも会社でも、アドレスの後半 64 ビットが同じになる。Web サイト側から見れば、ネットワークが変わっても同じ端末だと分かってしまう。IPv4 では NAT がたまたまこれを隠していた。

そこで RFC 8981（プライバシー拡張）で、インタフェース ID をランダムに生成し、一定時間ごとに作り直す方式が定められた。Windows・macOS・iOS・Android・主要な Linux ディストリビューションはこれを既定で有効にしている。

運用への影響：アドレスが定期的に変わるということは、IP アドレスを頼りにした端末の特定ができなくなるということ。ファイアウォールで端末を IP 指定するのは現実的でなくなり、アクセスログから「どの端末か」を追うのも難しくなる。
サーバ側は安定したアドレスが要るので、プライバシー拡張を無効にするか、固定アドレスを手動設定する。「クライアントは変わる、サーバは固定」で使い分ける。
