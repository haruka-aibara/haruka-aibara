エニーキャスト

世界中の DNS サーバが同じ IP アドレスを名乗っている。それでも正しく届く理由。

「いちばん近いサーバに届いてほしい」

DNS のルートサーバや CDN のように、世界中から大量のアクセスを受けるサービスがある。日本からのアクセスがアメリカのサーバに飛べば遅いし、そこが落ちれば日本からも使えなくなる。

解決策として、DNS で地域ごとに違う IP を返す方法もある。しかしそれは名前解決の時点での判断なので、キャッシュが効いていると切り替わらない。

エニーキャストは発想が違う。複数のサーバに同じ IP アドレスを付け、経路制御（ルーティング）に「いちばん近い 1 台」を選ばせる。アドレスは 1 つなので、利用者側は何も意識しない。

使いどころが限られる理由

経路が変わると途中で接続先のサーバが入れ替わる可能性がある。セッションを持たない通信なら問題ないが、ログイン状態を保つような通信では相性が悪い。

このため、エニーキャストが向くのは次のような用途になる。

  • DNS — 1 往復で完結する。ルートサーバや 8.8.8.8 はこの方式
  • CDN のエッジ — 静的コンテンツ配信
  • DDoS の吸収 — 攻撃トラフィックが世界中の拠点に分散するので、1 拠点に集中しない

IPv6 では仕様としてエニーキャストが定義されている（IPv4 では BGP の運用で実現している）。IPv6 のアドレス種別はユニキャスト・マルチキャスト・エニーキャストの 3 つで、ブロードキャストは存在しない。
