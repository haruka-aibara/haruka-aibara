DNS

通信には相手の IP アドレスが要る。でも人間が覚えているのは名前だけ。名前から IP を引く電話帳が DNS。

名前と IP アドレスの対応表を、誰が持つか

「www.example.jp に接続したい」と思っても、パケットの宛先に書けるのは IP アドレスだけ。名前 → IP の変換（名前解決）がすべての通信の前に挟まる。

問題はこの対応表の管理方法。世界中の名前を 1 か所の表で管理するのは、量的にも更新頻度的にも無理がある。そこで DNS は名前を階層構造にして、階層ごとに管理者を分けるという設計を取った。

引くときは根から順に辿る

名前解決は、この木をルートから順に「次はどこに聞けばいいか」を教えてもらいながら降りていくことで行われる。ただし毎回端末がそれをやるのではなく、代行するサーバと役割分担がある。登場人物は DNS サーバの 3 つの役割 にまとめた。

一度引いた結果は各所でキャッシュされるので、実際にルートまで辿る問い合わせはごく一部で済む。
