DNS サーバの 3 つの役割

「DNS サーバ」と一口に言うが、答えを持っている者・代わりに調べ回る者・頼むだけの者は別物。トラブル時に「どの DNS が悪いのか」を切り分けるにも、この区別が前提になる。

頼む・調べる・答えるの分業

名前解決には 3 種類の登場人物がいる。

  • スタブリゾルバ — 端末の OS に入っている問い合わせ係。自分では調べず、決められたサーバに「全部調べて答えだけちょうだい」と丸投げする（再帰的問い合わせ）
  • キャッシュサーバ（フルサービスリゾルバ） — 丸投げを引き受けて、ルートから順に権威サーバを辿って調べる係（反復問い合わせ）。結果を TTL の間キャッシュする
  • 権威サーバ（コンテンツサーバ） — 自分が管理する範囲（ゾーン）の対応表の原本を持ち、それについてだけ答える係

役割が分かれているから、対策も分かれる

持っているものどこにある
スタブリゾルバ問い合わせ先の設定だけ端末の OS 内
キャッシュサーバ調べた結果のキャッシュ社内・ISP・パブリック DNS（8.8.8.8 など）
権威サーバゾーンの原本ドメインの管理者側

攻撃も役割ごとに違う。キャッシュサーバには偽の答えを覚え込ませるキャッシュポイズニング（カミンスキーアタックと DNSSEC）、外に開きっぱなしのキャッシュサーバはオープンリゾルバとして踏み台になる。
